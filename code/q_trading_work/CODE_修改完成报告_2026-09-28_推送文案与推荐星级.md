### 2.1 文案拼装下沉到通知器

原来 `_save_trade_signal` 里手拼字符串：

```python
notify_msg: str = f"交易信号: {action} code={code} price={price:.2f} reason={reason}"
if signal_type == "SELL":
    notify_msg += f" 收益率={profit_rate:.2f}%"
```

现在改为传字段，由 `TradeNotifier.format_signal_message()` 生成。原因是本次格式里出现了**股票名称**，而名称要么由调用方查、要么由通知器查；放在展示层（通知器）可以顺带做缓存，调用方不必关心接口。

```python
@staticmethod
def format_signal_message(action, code, price=0.0, reason="", star=0.0,
                          stock_name="", profit_rate=None) -> str:
    name_part: str = f"({stock_name})" if stock_name else ""
    message: str = f"{action}{code}{name_part}"
    if price > 0:
        message += f"，{action}价:{price:.2f}"
    if reason:
        message += f",{action}条件：{reason}"
    if star > 0:
        message += f"，{action}推荐: {star:g}颗星"
    if profit_rate is not None:
        message += f"，收益率:{profit_rate:.2f}%"
    return message
```

分隔符是照用户目标串逐字符对齐的（首段后是「，」、价格段后是半角「,」、条件段后是「，」）。如果需要把字段分隔统一成全角「，」，只改这个方法里的两处字符串拼接，测试 `test_matches_user_confirmed_sample` 同步改期望串即可。

### 2.2 股票名称的取值链

`_resolve_stock_name(code, name="")` 的优先级：

1. 调用方显式传入（保留给将来策略侧直接给出名称）；
2. 实例缓存 `self._stock_name_cache`；
3. `/api/stock_info/code` 查询（与 `TradeManager._get_stock_name` 同源，走 `AppContext().stock_info_api`）。

查询失败（含 `AppContext` 未初始化、接口异常）返回空串并做**负缓存**，文案退化成不带括号的纯代码。名称只是文案修饰，取不到不能影响推送本身。

缓存是必须的：推送发生在分钟级信号链路上，同一只股票一天可能反复触发，不缓存就是每条信号多打一次 HTTP。实测同一实例内第二条推送（卖出）命中缓存，接口调用次数保持 1。

### 2.3 `notify` 的兼容边界

```python
def notify(self, message: str = "", recipient=None, user_strategy_id="", *,
           action="", stock_code="", stock_name="", price=0.0,
           reason="", star=0.0, profit_rate=None) -> None:
```

- `action` 与 `stock_code` 同时非空 → 忽略 `message`，按上面的格式重排；
- 只传 `message` → 原文推送，`TradeManager` 的成交通知（买入/卖出成交回执）走这条路径，文案不变；
- 两者都空 → 记 warning 跳过，不发空消息。

`message` 由位置参数改为带默认值，是本次唯一签名变化；`TradeManager` 与测试里既有调用都是 `notify(text, recipient=...)` 形式，位置参数仍是第一个，不受影响。

### 2.4 字段缺失时的降级

| 情况 | 输出 |
| --- | --- |
| 名称取不到 | `买入002050.SZ，买入价:…`（无空括号） |
| `price <= 0` | 省略价格段 |
| `star <= 0` | 省略推荐段（不显示「0颗星」，避免被读成「不推荐」） |
| `profit_rate is None` | 省略收益率段（买入侧传 None） |
| `reason` 为空 | 省略条件段 |

星级格式用 `:g`：整数星级显示 `3颗星`（与样例一致），带小数则显示 `3.5颗星`。策略侧 `star = score / 2`，会出小数。
