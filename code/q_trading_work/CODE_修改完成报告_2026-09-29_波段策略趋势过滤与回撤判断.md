## 二、枢轴点因子诊断

### 2.1 实测方法与数据

8 只股票、588 个交易日（2026-05-01 ~ 09-28 的服务端日K快照）。对每个交易日用**前一交易日**的
H/L/C 建枢轴，再用当日 OHLC 四个价格点及区间 20 点均匀采样打桩，直接调用
`InDaySRFactor.score_with_sr()`，不重写公式。

修改前的分布：

| 分值 | OHLC 采样占比 | 均匀采样占比 |
| --- | --- | --- |
| −10 | 1.5% | 1.3% |
| −7.5 | 5.4% | 4.7% |
| −5 | 9.9% | 9.9% |
| **0** | **61.9%** | **64.8%** |
| +5 | 13.4% | 12.7% |
| +7.5 | 6.9% | 6.0% |
| +10 | 1.0% | 0.6% |

辅助数字：档位距枢轴点的幅度 `r1` 中位 **1.42%**、`s1` 中位 1.51%、`r3` 中位 **5.81%**（p95 达 18.15%）；
0 分采样点相对枢轴点的偏离中位数只有 **0.65%**；昨日振幅 D 中位 **2.90%**。
全天恒 0 分的交易日占 **20.2%**。

### 2.2 根因

原实现的档距是「昨日振幅」的倍数：`r2 = P + D`、`r3 = P + 2D`，`r1/s1 = 2P−L / 2P−H`。
`r3` 要求价格偏离枢轴点约 5.81%（中位）才触发，属于统计意义上的准死档。

而 `BollSRFactor` 的档距是**分钟序列自身波动率**的 1.0σ/1.5σ/2.0σ。10 根分钟收盘的 σ 通常在
0.3%~0.5% 量级，因此布林带在枢轴点还停在 0 分档时就已经给出 −5 或 −7.5。
两个因子等权平均（`avg_score = (inday + boll) / 2`）后，枢轴点为 0 相当于弃权，
信号的符号与档位完全由布林带决定。这与你看到的现场一致：
`枢轴点分值:0.00, 布林带分值:-7.50, 平均分值:-3.75`。

需要说明的是，因子本身**没有实现缺陷**：档位可达（非恒不可达）、空表与 NaN 有保护、
`shift(0)` 取的确实是前一交易日（`load_his_daily_data` 的 `end` 恒为前一交易日）。

### 2.3 顺带发现并修掉的缺陷

昨日 H=L（一字板、停牌后无成交、数据缺失）时 D=0，`r1 = r2 = r3 = pivot`，
`price >= r3` 等价于 `price >= pivot`，恒成立，于是**恒定返回 −10「极度超买」**。
涨停一字板会被判成卖点。已在 `score_with_sr` 入口加保护：`r1 <= s1` 时返回 0.0。

这里刻意**不新增「振幅」列**来判定，而是用 `r1 <= s1` 反推：Redis 里已按
`to_json(orient="records")` 存了旧格式的点位表，新增列在旧缓存上读不到会退化成
「恒 0 分」，比原问题更难排查。

### 2.4 倍数选择

先扫描候选倍数（同一快照，判定链不变，只换档位价格）：

| 倍数（m1/m2/m3） | 0 分占比 | +10 / −10 占比 | 全天恒 0 交易日 |
| --- | --- | --- | --- |
| 经典（原实现） | 64.3% | 0.7% / 1.3% | 20.2% |
| 0.25 / 0.50 / 0.75 | 35.2% | 12.1% / 9.9% | 1.2% |
| 0.30 / 0.60 / 0.90 | 41.5% | 8.6% / 7.4% | 3.4% |
| **0.33 / 0.66 / 1.00（采用）** | **45.4%** | **6.8% / 6.1%** | **4.8%** |
| 0.40 / 0.80 / 1.20 | 52.4% | 4.4% / 4.3% | 7.7% |

**为什么不用 0.40/0.80/1.20**：价格落在昨日区间内时，它相对枢轴点的偏离有数学上界
`|price − pivot| <= 2D/3`（`P−L = (D+C−L)/3 ∈ [D/3, 2D/3]`，`H−P` 同理）。
所以 `m > 2/3` 的档位必然要求价格**突破昨日高低点**才能触及。0.40/0.80/1.20 组里
第二档（0.8D）就已越过这条线，两档都成了「破位档」，0 分占比因此只降到 52.4%。

采用 0.33/0.66/1.00 后每个倍数都有清晰语义：1/3 振幅约等于昨日区间内的中性偏离，
2/3 振幅是区间内的极值偏离，1 倍振幅明确对应「突破昨日区间」。
该契约已固化成断言 `R1_RATIO <= 2/3`，防止后人调大后档位再次退化。

### 2.5 修改后的实测

| 指标 | 修改前 | 修改后 |
| --- | --- | --- |
| 0 分采样点（OHLC / 均匀） | 61.9% / 64.8% | **44.2% / 45.1%** |
| ±10 档占比（OHLC） | 1.5% / 1.0% | **7.0% / 7.9%** |
| 全天恒 0 分的交易日 | 20.2% | **4.6%** |
| `r1 − pivot` 中位 | 1.42% | 0.96% |
| `r3 − pivot` 中位 | 5.81% | 2.90% |

## 三、趋势过滤

### 3.1 判定口径

`ADX(14) >= 25` 且 `−DI > +DI` 判为下跌趋势。两个条件缺一不可：

- 只看 `−DI > +DI`：震荡市里 DI 频繁交叉，会随机剔掉一半股票，与本策略「只在震荡市用」的定位相悖；
- 只看 `ADX > 阈值`：只说明「有趋势」，上涨趋势正是本策略想参与的突破行情，不该禁。

ADX 或 DI 为 NaN（次新股、停牌复牌、取数不足）时比较恒为 False，判不出趋势即**不过滤**。
这是有意的 fail-open：数据缺口不该被当成下跌信号把股票整个禁掉。

### 3.2 生效位置

两处都用同一个 `_is_downtrend`：

| 链路 | 位置 | 作用 |
| --- | --- | --- |
| 选股 / 回测 | `is_match_strategy` 的条件 0 | 下跌趋势的股票不入选，且排在市盈率查询之前（省一次 HTTP） |
| 盘中 | `handle_minute_bar` 读 `_downtrend_codes` | 当天不做买入判定 |

**卖出与风控判定不受趋势闸门影响**（按你选的口径）。下跌趋势里支撑位会被逐个跌穿，
持仓此时恰恰需要靠支撑位跌破与回撤止损离场，把卖出一并关掉等于让持仓失去保护。

日K只取一次（`_trend_kline_days()` 根，默认 40 根），同时喂给枢轴点计算与趋势判定：
两者根数需求不同（枢轴点只要前一交易日 1 根，ADX 要 2×period = 28 根），
分两次取数会让盘前多打一轮 HTTP，且同一只股票可能在两条链路里拿到不同快照。

趋势向下的股票会记一条 INFO 日志（`cfg/log.yaml` 的 info.log 是 INFO 级），
这是「为什么这只股票今天没有买入信号」的唯一解释。

## 四、回撤判断

### 4.1 融入方式

`final_score = (枢轴点分 + 布林带分) / 2 + 回撤分项`，回撤分项**叠加**而不是做平均。
止损要的是果断退出：一条回撤理由（−6.0）就应足够单独触发卖出（阈值是「< 0」），
不该被「枢轴点 = 0、布林带 = 0」的中间态稀释掉。

| 分项 | 参数 | 默认 | 触发条件 |
| --- | --- | --- | --- |
| 个股回撤 | `sell.drawdown_pct` / `sell.drawdown_score` | −6.0% / −6.0 | 现价相对持仓期间最高价跌幅超过阈值 |
| 账户回撤 | `risk.max_drawdown_pct` / `risk.drawdown_score` | −10.0% / −6.0 | 账户权益自峰值回撤达阈值（0 或正数关闭） |

**未触发回撤时 `final_score` 恒等于位置分，卖出行为与改动前完全一致**，
推送文案也逐字保持原样；回撤段只在触发时追加在后面：

```
条件满足: 枢轴点分值:0.00, 布林带分值:-7.50,平均分值:-3.75，持仓回撤-9.09%(最高11.00→10.00，阈值-6.00%，扣-6.00分)
```

### 4.2 持仓最高价口径

个股回撤基准用 `BaseStrategy._resolve_highest_price`：有持仓时取 `[buy_time, 当日]` 的
日K最高与当日最高取大；实时链路恒传空持仓（设计约定 D-1），基准退化为「最近 2 个交易日」。
查询失败时回退到 `max(当日最高价, 成本价)`，回撤口径退化为日内回撤，判定仍然可用。

该方法原为 `VolumeExpansionStrategy` 私有实现，本次**上移到基类**供波段策略复用。
两处各写一份时，查询区间与缓存 key 一旦漂移，同一持仓在两个策略里会得到不同的回撤数字，
而两边日志都看起来正常。同批把「无持仓时回退最近 2 个交易日」的逻辑也提到基类
（`_sell_baseline_buy_time`），成交量策略改为调用同一份。

账户回撤由外部注入（`StrategyWorkflow._refresh_account_drawdown` 在 `_process_bar`
调用策略前设置，回测侧是 `BacktestEngine` 的 `set_account_drawdown`），
两处都是通用的，不区分策略类型，因此波段策略无需额外接线。

## 七、部署与回归注意

1. **枢轴点位缓存是旧格式**。Redis key 为 `波段交易策略:sr_points:{owner}:{code}`，TTL 6 小时。
   盘前 `before_trading` 会覆盖成新档位；若在**盘中**热更新代码，最多 6 小时内会读到旧点位，
   期间判定用的是新逻辑配旧数值。建议盘后或盘前更新。

2. **服务端模板 `default_params` 未同步**。实盘参数走三级回退
   （用户策略 `strategy_params` > 模板 `default_params` > `cfg/strategy.yaml`），
   新字段在模板里不存在时由**类属性兜底**，因此实盘会按本次的默认值生效。
   但三处不一致本身就是隐患（记忆里已固化成不变量）。波段模板 ID 为
   `6a662b9b28893aa08cf31092`，建议通过管理端或 `PATCH /api/strategy/{id}` 把
   `match.trend_*` / `sell.drawdown_*` / `risk.*` 一并写入，需要 `admin_token`。

3. **账户回撤是本次新启用的全局卖出条件**（阈值 −10%），对所有持仓股成立。
   语义是「整体降仓」，不冻结开新仓。若要关闭，把 `risk.max_drawdown_pct` 设为 0。

4. **日频回测不会调用策略的卖出逻辑**（只调 `before_trading` 与 `select`），
   因此个股回撤在日频回测里不生效；账户回撤通过 `_apply_drawdown_exit` 重放仍然生效。
   趋势过滤在 `is_match_strategy` 里生效，会实际改变回测选出的股票集合。
   凡靠卖出规则控回撤的策略，日频回测结论必然失真，这点在成交量策略的报告里已记录。

5. **参数 14/25 是经验值**，没有针对股票池做回测校准。趋势过滤的松紧直接影响信号量，
   建议在「我的科技股票池」上跑一轮 `--strategy swing` 对照（关趋势 / 开趋势），
   按信号数与胜率决定是否调 `trend_adx_threshold`。

## 八、未覆盖 / 待确认

1. `strong_rebound_strategy` 保有自己的 `_resolve_highest_price`（带 `_highest_prices`
   内存兜底，日K接口异常时仍能追踪盘中最高）。本次未统一，两者在接口异常时的降级行为不同：
   基类版本退化为日内回撤，强趋势版本用内存累加。若要完全统一需改造强趋势侧，会影响其 63 个测试覆盖的降级链。
2. 趋势过滤目前是「全池逐股日线 ADX」，没有做池级别的市场状态判断（例如大盘或板块趋势）。
   若你希望「整体转弱时整池降频」，那是另一套机制。
