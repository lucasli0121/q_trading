### 2.2 实测：窗口长度 × 趋势分

构造加速上涨日线序列（`adx_period=7 / vwap_period=7 / high_low_period=7`，与 `cfg/strategy.yaml` 的 `trend_days_limit: 7` 一致）：

| 窗口 | 趋势分 | `macd_hist` | 前一根 `macd_hist` |
| --- | --- | --- | --- |
| 20 | 6.50 | nan | nan |
| 34 | 6.50 | 0.0791 | **nan** |
| 40 | 9.50 | 0.0858 | 0.0846 |
| 60 | 9.50 | 0.1047 | 0.1041 |

下跌序列（40 根）得分 0.0。

### 2.3 前一轮报告的口径需要修正

前一轮写的是「MACD 需 34 根（26+9−1）」。实测表明 **34 根仍然拿不到那 3 分**：

判定是 `hist > 0 且 hist > 上一根的 hist`，34 根时当根 `hist` 有值，但前一根仍是 NaN，`NaN > NaN` 为 False。真正需要的长度是 **35 根**（34 根出值 + 1 根用于比较放大）。窗口取 40，余量 5 根。

20 根（6.50）与 40 根（9.50）相差正好 3.0 分，即 MACD 那一项。这条已经写进类 docstring，并用 `tests/factor/test_multi_trend_factor.py::TestMultiTrendWindowContract` 锁住长度门槛。

### 2.4 副作用

- **趋势分上限由 7.0 回到 10.0，而 `up_trend_score` 仍是 6.0**。达标门槛从「可达上限的 86%」降到 60%，选中的股票数会增加。本轮按决定只放大窗口，阈值未动。
- **回测交易数会减少**：`signal_window` 放大后，回测起始 40 根（原 20 根）内的信号点被 `i < signal_window` 跳过。
- **取数区间够用**：`load_his_daily_data` 的回溯长度是 `days * 2`，40 根对应 80 个自然日，覆盖 40 个交易日（含长假）有余。
- **其余因子不受影响**：`LowReboundFactor` 只看 `low_arr[-5:]`（`consecutive_days: 5`）；`_match_pe_profit` 不吃日线窗口；`KlineSRFactor` 在强反弹策略中已不使用。日线窗口只影响 `MultiTrendFactor`。

### 2.5 顺带修掉一个索引对齐隐患

`multi_trend` 里 `prev_high` / `prev_low` 原先写作：

```python
result_df['prev_high'] = stock_data['high'].rolling(self.high_low_period).max()
```

`result_df` 的索引是 `0..n-1`（其余列都来自 talib 的 ndarray，按位置对齐），而 `stock_data` 的索引未必从 0 开始（调用方传切片时是 `i..j`）。把 Series 直接赋给列时 pandas **按索引对齐**，只会保留与 `0..n-1` 重叠的那段，且值整体前移 —— 前高实际取到的是窗口前部的价格，档位判定随之失真，不抛任何异常。

已改为 `.to_numpy()`。当前两条链路（`to_dict(orient="records")` 与 `pd.DataFrame(list[dict])`）恰好索引都从 0 起，输出未受影响，属加固；新增用例 `test_sliced_index_does_not_shift_prev_high` 覆盖切片输入。

### 3.3 关键：`0` 与「未配置」必须分开

这两个值是**语义相反**的：

- 显式 `0` = 限制买入，策略只卖不买
- 字段缺失 = 未配置，走默认（不限制 + 10 万），策略可以下单

原实现 `float(raw_initial or 0)` 把「字段缺失」变成 0，而 0 在本项目语义里恰好是「限制买入」，结果是未配置的策略静默不下单（`6a58d62b…` 0/0 即此类）。现在所有解析入口一律「仅 `None` / `""` / 非数字落默认」，并且**禁止用 `or` 兜底** —— `raw or DEFAULT` 会把显式配置的 0 洗成默认值，让「限制买入」静默失效，这类错误不报错、只在行为上相反。

`dao/user_strategy_dao.py` 的 `__init__` 默认值是真入口：`@dataclass` 用 `_set_new_attribute` 装配生成的 `__init__`，不会覆盖类体里已手写的同名方法（实测签名确认）。

### 3.4 存量数据

本次改的是**默认值**，覆盖面是「今后新建的记录」与「字段缺失的记录」。已经写入库、字段里明确存着 `0` / `0` 的记录不在此范围内，仍按 `0` = 限制买入 执行。要让这些策略开始下单，需要改库或经管理端重新保存。`6a58d62b…` 属这一类。
