## 二、recipient 改用用户策略名

### 2.1 两处来源

| 位置 | 原来的取法 | 现在 |
| --- | --- | --- |
| `StrategyWorkflow._save_trade_signal` | `recipient=user_strategy_name or strategy_name`，用户策略名为空时回退到策略模板名 | `recipient=user_strategy_name`，为空时兜底查一次 `/api/user_strategy/get` 的 `name`，**不回退模板名** |
| `TradeManager._get_strategy_name` | 先查 user_strategy 拿 `strategy_id`，再查策略模板拿 `name`，返回的是**模板名** | 改名 `_get_user_strategy_name`，直接取用户策略记录本身的 `name` |

`TradeManager` 那处是这次要改的关键：方法名虽然叫「策略名」，实际返回的是模板名（`/api/strategy/get` 的 `name`），所以成交回执的 recipient 一直显示「波段交易策略」。现在只查一次 `/api/user_strategy/get`。实测模板查询次数为 0。

`StrategyState.user_strategy_name` 在 `_load_user_strategy`（`us_item.get("name")`）与 `add_user_strategy`（`user_strategy.name`）两处填充，正常路径不需要兜底查询；兜底只覆盖旧调用点，且加了 `isinstance(us_info, dict)` 判断，接口返回异常结构时保持空串，不会把 Mock 或畸形对象写进 recipient。

兜底也拿不到时 `recipient` 为空，通知器显示 `default`（原有行为），至少不会显示成模板名。

缓存变量 `_strategy_name_cache` 一并改名为 `_user_strategy_name_cache`，避免名字继续误导。

```
recipient=爸爸的波段交易
```

## 三、成交回执文案

### 3.1 格式（用户确认：同构 + 字段全保留）

买入：

```
买入000001.SZ(平安银行)，成交价:10.50,数量:100,状态:成功，时间:2026-09-28 10:00:00
```

卖出：

```
卖出000001.SZ(平安银行)，成交价:12.00,数量:100,持仓价:10.20,状态:成功，收益:200.00(20.00%)，时间:2026-09-28 10:00:00
```

与原格式的差异：

- 加股票名称（走与信号推送同一份 `_resolve_stock_name` 缓存）；
- 「时间:… 股票:… 买入 数量 …」的标签式写法改为「动作+代码(名称)，成交价:…」；
- 收益率由 `:.4%`（`20.0000%`）改为 `:.2%`（`20.00%`）；
- 买卖共用一条拼装路径，差异只在「持仓价 / 收益」两组字段的有无，买入传 `None`。

### 3.2 接口调整

上一轮把信号的结构化字段直接挂在 `notify()` 上。现在有两种文案，`notify()` 恢复为「只负责发送」，两个语义化入口各管一种：

| 方法 | 文案 |
| --- | --- |
| `notify(message, recipient, user_strategy_id)` | 只发送，文案由调用方给出（自定义文案走这条） |
| `notify_signal(action, code, price, reason, star, profit_rate, …)` | 交易信号 |
| `notify_trade_result(action, code, price, quantity, status, position_price, profit_amount, profit_rate, create_time, …)` | 成交回执 |

两个入口内部都调用 `format_*_message()` 完成拼装与名称解析，调用方只传字段。

调用点：`StrategyWorkflow._save_trade_signal` → `notify_signal`；`TradeManager._execute_and_notify` → `notify_trade_result`（原来买卖两个分支各拼一次字符串，现在合并成一次调用）。

## 五、未做与注意

1. `TradeManager._strategy_api` 现在没有调用方了（原来只有 `_get_strategy_name` 用它）。作为实例属性保留，没有删除，避免影响外部引用；要清理可以连同 `StrategyApi` 的 import 一起去掉。
2. 成交回执的 `持仓价` 只在卖出时显示（原实现也是），买入时成本价即成交价，没有重复显示。
3. 用户策略名解析失败时 recipient 为空、显示 `default`。这条路径只在 `/api/user_strategy/get` 不可用时出现，此时信号落库与推送照常进行，不会因为拿不到名字而中断。
