# 日内形态因子接入（2026-10-18）

把 `_shape_stats.py` 的形态编码抽成 `factor/intraday_shape_factor.py`，接入成交量策略
买入侧。核心决定是「形态只调整买入门槛，不改综合分」。

## 一、口径

编码层面（四个量，与归档字段同名）：

| 量 | 公式 | 分档阈值 |
| --- | --- | --- |
| gap | 当日开盘 / 前收 − 1 | ±0.5% |
| trend | 当日收盘 / 当日开盘 − 1 | ±0.5% |
| close_pos | (收盘 − 最低) / (最高 − 最低) | 0.33 / 0.66 |
| shape | 四段符号（早盘 / 上午尾 / 午后 / 尾盘各 1 小时） | 单段 ±0.2% |

字段语义的前提：分钟表里 `open` 是当日开盘价（全天所有 bar 同值），
`high` / `low` 是当日累计值，只有 `close` 逐 bar 变化。所以日内路径只能用 close 序列。

模式分两种：

- **完整模式**（`as_of` 为空）：要求末根 >= 14:30，用于收盘后统计
- **前缀模式**（传 `as_of`）：只用截至该时刻的 bar，用于盘中

前缀模式下末根所在的那一段「进行中」，给真实符号但不计入 `shape`；尚未开始的段
用 `_` 占位。11:00 时 `prefix_shape = "+0__"`。

**规则口径统一用「前 N 段符号」**（默认 N=2）。理由：`gap_b` 盘中稳定（开盘价与前收
固定），但 `trend_b` / `close_pos` 是「截至当前」的统计量，10:30 与 14:30 含义不同。
用三元组当规则键会让同一只股票在盘中不同时刻命中不同规则，而历史统计只对应收盘
那一刻。前两段符号在 11:30 定型后不再变化，规则效果与查询时刻无关。

## 二、接入点

`VolumeExpansionStrategy._check_buy_conditions`：

```
buy_threshold = MIN_SCORE + buy_threshold_offset(code) + shape_offset
```

`shape_offset = SHAPE_MAX_OFFSET × (5 − shape_score) / 5`，正 = 更难买。

**为什么不做成 combined 的加减项**：`BASE_SCORE == MIN_SCORE == 5.0`，两道门槛通过时
combined 恒 >= 5.0。给它减 0.5 等于把「刚好达标」的单子全部毙掉（负修正即硬否决），
加 0.5 不改变任何判定、只改星级。加在门槛上语义明确。

**当前结构下只有收紧有效**：好形态的负偏移把门槛压到 5.0 以下，而两道门槛通过已经
保证 combined >= 5.0，压门槛不产生额外买入。要让「形态好 ⇒ 多买」生效，必须下调
`BASE_SCORE` 让综合分底分低于门槛，这会影响所有现有回测，属独立改动。

形态不可用（数据不足、前 N 段未走完、计算异常）时偏移为 0，fail-open，与
`buy_threshold_offset` 的缺省语义一致。

信号明细新增三个字段，日志与推送可见：`shape`（前两段符号）、`shape_score`、
`shape_offset`。

## 三、统计结论（前缀口径）

2026-07-17 ~ 10-13，40 个交易日、593 个「前两段已定型」样本、次日超额收益：

| 键 | 日度超额% | 日度数 | t | 前后半段 |
| --- | --- | --- | --- | --- |
| 0+ | −0.830 | 8 | −0.95 | 同号但只有 8 天 |
| +− | −0.255 | 28 | −0.62 | 反号（+0.708 / −0.137） |
| **++** | **+0.960** | **24** | **2.00** | **同号（+1.023 / +0.872）** |
| −− | +0.231 | 24 | 0.69 | 同号 |
| +0 | +0.562 | 18 | 0.73 | 反号 |

只有 `++` 同时满足「t 到 2、前后半段同号、两段幅度接近、日度数 24」。

完整口径下 `++++`（全天单边上涨）次日 **−1.21%**，与 `++` 的 +0.96% 符号相反。
含义是「上午就走强」与「一路涨到收盘」不是一回事，后者更像情绪过热。
这也说明完整形态的统计结论不能直接搬到盘中。

## 四、为什么默认规则表为空

`++` 是正向规则，而当前结构下正向不产生买入效果。填进去只会让 `detail` 里多一句
`形态6.5（前2段++）`，对交易结果零影响。填负向规则又只有 `+−`（t=−0.62，反号）
可选。两个选择都不比空表更好。

所以默认空表（形态恒中性），规则通过 `factor/intraday_shape_factor.py` 的
`DEFAULT_PATH_RULES` 或构造参数填入。

## 六、待决策

要让「上午走强」的 +0.96% 真正转化为交易收益，需要把形态分纳入综合分，前提是

## 七、路径判据与跨日序列（2026-10-18 晚）

前六节的口径有一处缺陷被指出：**用 `开盘价 / 昨收` 判不出「高开低走」**。

### 7.1 反例与三个新量

用户给的反例：平开或低开，9:30–10:30 冲高形成全天最高点，之后一路震荡下跌，
收盘低于开盘。按旧口径它是「平开」+「走弱」，交易含义（上方有派发）完全没表达。

具体化成一个可复现的例子（本仓库测试 `tests/test_intraday_shape_sequence.py`）：

| 时点 | close | 说明 |
| --- | --- | --- |
| 09:30 | 10.00 | 平开（preclose = 10.00） |
| 10:20 | 10.40 | 全天最高，比开盘高 4.0% |
| 15:00 | 9.90 | 收盘低于开盘 1.0%，距峰值回撤 4.8% |

`gap = 0`、`trend = −1.0%`、`close_pos = 0（收在下沿）`，三个旧字段都不足以区分
它和「平开后缓跌 1%」。

新增两个量，都从 close 序列取：

| 量 | 公式 | 说明 |
| --- | --- | --- |
| `peak_seg` | `argmax(close)` 落在哪一段（0..3） | 峰值时刻。分钟表的 `high` 是当日累计值，argmax 永远在末根，定位不了时刻 |
| `fall_from_peak` | 收盘 / 日内最高 close − 1 | 从峰值回撤，≤ 0 |
| `peak_rise` | 日内最高 close / 当日开盘 − 1 | 峰值相对开盘的涨幅 |

判据：

```
dive = peak_seg <= 1（早盘或上午尾见高）
       且 peak_rise >= 0.5%
       且 fall_from_peak <= -2.5%
```

`peak_rise` 是必需的第三条。只看「峰值在首段 + 回撤深」会把**开盘即最高、一路阴跌**
也判成冲高回落（它的 peak_seg 也是首段、回撤同样深），结果是所有单边下跌日都变成
「高开低走」，「低开低走」这个标签永远取不到。实测加上这一条后：低开低走从 76 个
样本升到 118 个、走弱从 87 升到 132，高开低走从 488 降到 400。

### 7.2 日形态标签

一天一个互斥标签，判定顺序：

1. 收盘下跌（`trend <= −0.5%`）
   - `dive` 成立 ⇒ **高开低走**（**不看 gap**，这是本次修正的核心）
   - 否则低开 ⇒ 低开低走 / 高开 ⇒ 高开低走 / 平开 ⇒ 走弱
2. 收盘上涨 ⇒ 低开高走 / 高开高走 / 走强
3. 其余 ⇒ 震荡

弱势标签 = {高开低走, 低开低走, 走弱}，强势 = {低开高走, 高开高走, 走强}。

阈值来历（2026-07-20 ~ 10-12，1514 个股票-日）：

- `fall_deep = 2.5%`：从日内最高 close 回撤的 25 分位是 −3.37%、中位数 −1.77%。
  取 1% 会让 54.5% 的样本都算「冲高回落」，这个标签就退化成「今天不是单边上涨」；
  取 2.5% 命中 33.6%，与「上方有派发」的直觉一致。阈值是分位数口径，换股票池要重算。
- `peak_rise = 0.5%`：小于这个幅度谈不上「冲高」。

标签分布（同一段样本）：

| 标签 | 样本 | 占比 |
| --- | --- | --- |
| 高开低走 | 400 | 26.4% |
| 低开高走 | 240 | 15.9% |
| 高开高走 | 219 | 14.5% |
| 走强 | 213 | 14.1% |
| 震荡 | 192 | 12.7% |
| 走弱 | 132 | 8.7% |
| 低开低走 | 118 | 7.8% |

日标签只在**已收盘**时产出（末根 ≥ 14:30）。前缀模式下恒为空：盘中峰值可能后移、
回撤可能变浅，此时的标签不是「这一天的形态」。注意 `dive` 判据本身在盘中可用
（一旦成立就保持收紧），但它会因创新高而撤销。

### 7.3 跨日序列为什么值得做

昨日及更早的形态是**隔夜已定型**的信息，盘中任何时刻都一样。这绕开了前几节那个
限制：当日前缀形态要等 11:30 前两段走完才可用，样本也要先按「前 N 段是否走完」筛
一遍；跨日序列没有这个问题，且每天每股一个观测。

实现分两层：

- `factor/intraday_shape_factor.py::sequence_features()`：纯计算。输入标签序列
  （昨日在前），输出 `weak_streak`（连续弱势天数）、`decay_weak`（日衰减 0.6 的加权
  弱势分）、`prev_day_type`、`seq`（`|` 连接的标签串）。
  空串（那天算不出来）**中断连续计数**而不是被跳过——不知道那天的形态，就不能假定
  它延续了前一天的弱势；但权重位置照常按时间推进。
- `dao/shape_history_dao.py::ShapeHistory`：读归档 parquet 并按 `(code, date)` 缓存
  日标签。只读 `[local_hq] root`，不连服务端 HTTP：分钟数据服务端只留 90 天且无回源
  路径，逐股打 HTTP 会让每分钟的买入检查变成网络阻塞。`labels(code, today)` 只返回
  `today` 之前的日子，回测里归档含未来日期也不会读到。

接入：`shape_offset = max(当日层偏移, 跨日层偏移)`，**不叠加**。两者是「形态风险」的
同一维度证据，相加会重复计数；而且 `MIN_SCORE` 是 5 分制，两层各 1.0 叠起来很容易
把门槛抬到当天买不进。

### 7.4 统计结论：编码成立，交易含义不成立

同一段样本（39 个交易日 / 1514 个股票-日 / 160 只股票），三张表的关键行：

**① 日形态 → 次日超额**

| 标签 | 日度超额% | 日度数 | t |
| --- | --- | --- | --- |
| 走弱 | −0.511 | 27 | −2.04 |
| 低开低走 | −0.364 | 27 | −1.29 |
| 低开高走 | +0.068 | 27 | 0.15 |
| **高开低走** | **+0.259** | **35** | **0.96** |

用户假设的「高开低走 ⇒ 后续走弱」，在次日尺度上符号相反（+0.259%），且不显著。
唯一 |t| 过 2 的是「走弱」（平开低走），但它与另外 6 个标签、2 个预测期一起比较，
属多重比较下的边缘结果。

**② 昨日形态 → 当日超额（今天开盘时可见的信息）**

全部 |t| < 1.1：高开高走 −0.443（t=−1.03）、高开低走 +0.261（t=0.97）、
低开低走 −0.083（t=−0.24）、走弱 −0.242（t=−0.98）。

**③ 截至昨日的连续弱势天数 → 当日超额**

| 连弱天数 | 日度超额% | 日度数 | t |
| --- | --- | --- | --- |
| 0 | −0.091 | 39 | −0.46 |
| 1 | +0.043 | 33 | 0.22 |
| 2 | +0.437 | 27 | 1.20 |
| 3 | +0.360 | 22 | 0.67 |

方向与假设**相反**且单调（连弱越多，当日反而略强），但都不显著。这与「高开低走次日
+0.259%」是同一件事：这段样本里短期是反转，不是延续。

结论：**编码口径按 7.1 修正成立**（用户对「gap 判不出高开低走」的判断正确），
但「连弱 ⇒ 压低买入预期」在这个样本里没有证据。因此默认规则表全空、
`shape_dive_score = 0`、`shape_seq_max_offset = 0`：机制完整可配，默认不参与判定。

### 7.5 开启方式

```yaml
# cfg/strategy.yaml  buy 节
    shape_dive_score: -2.0      # 当日冲高回落（回撤 ≥2.5%）→ 形态分 −2
    shape_seq_max_offset: 1.0   # 跨日层最差时抬高门槛 1.0
    shape_seq_rules:
      weak_streak: {2: -1.0, 3: -2.0}
      prev_day: {"低开低走": -1.0}
      sequence: {"低开低走|高开低走": -1.5}
```

跨日层还有前置条件：`cfg/stock.cfg` 的 `[local_hq] root` 必须指向归档目录（与回测
共用同一配置），否则跨日层自动关闭（fail-open，不影响当日层与其它判定）。

重新统计：

```bash
python _shape_stats.py --local-dir <归档根> --start 2026-07-17 --end 2026-10-13 \
    --min-days 5
```

输出里「日形态」「日形态 × 开盘缺口」「连续弱势天数」「截至昨日的连续弱势天数」
「昨日形态 → 当日超额」五张表是本节的证据来源。

### 7.6 局限与重估条件

- 39 个交易日的日度序列，7 个标签 × 2 个预测期 = 14 次比较。5% 水平下期望约 0.7 个
  假阳性，出现 1 个 |t| ≈ 2 属正常。
- 前后半段稳定性检验只做了四段路径，日形态与序列没做：分半后每组只剩 10~13 天。
- 结论是「这段样本里没有」，不是「这个机制无效」。日形态的样本门槛建议 200 个交易日；
  跨日序列的门槛相同，因为它按天计。
- 形态效应的方向可能随市场阶段变化（这段样本基准日均 −0.338%，整体偏弱）。换到上涨
  阶段应重跑，不能把当前符号当成常数。

## 八、跨日趋势判据：低于均线次数与高点低于前日次数（2026-10-19）

用户提出两个与日内路径、开盘缺口都无关的走弱判据：

1. 回看窗口内**收盘价低于 5 日均线的次数**，次数越多越弱
2. 回看窗口内**当日最高价低于前一日最高价的次数**，次数越多越弱

走强侧对称（高于均线、高于前日高点）；两边相等（收在均线上、高点打平）不计入
任何一侧——均衡不是偏强也不是偏弱。

### 8.1 与日形态标签的分工

标签回答「昨天是什么形状」，趋势判据回答「最近几天整体在走弱」。一只股票可以
连续几天都是「震荡」标签，同时收盘价一路低于 5 日线；后者才是「连续走弱」的
直接度量。两个子源数据源也不同：标签读分钟分区（`minute/YYYY/MM/`），趋势序列读
日K 分区（`day/YYYY/`），各自独立可用——分钟缺数据时趋势层仍然生效。

### 8.2 实现

- `factor/intraday_shape_factor.py::trend_features(daily, window)`：纯计算。日线序列
  升序输入，输出 `below_ma` / `above_ma` / `lower_high` / `higher_high` 四个计数。
  均线按**可用K线的位置**算（停牌日不在序列里，不按自然日对齐），因此读取层要多取
  `ma_period - 1` 天做种子，窗口内最早那天才算得出均线；不够时那些天只参与
  「低于前日高点」计数，均线计数跳过（不是判成「在均线上」）。
- `dao/shape_history_dao.py::daily_series(code, today, ma_period)`：读日K 分区，
  返回 today 之前最近 `lookback + ma_period - 1` 天的 `[{date, close, high}]`，
  按 `(code, today, ma_period)` 缓存。
- 规则表四张（`shape_seq_rules` 下新增键，键 = 次数下限，取满足的最大键）：
  `below_ma` / `above_ma` / `lower_high` / `higher_high`，默认全空。
- 加减分累加进跨日层的 `sequence_adjust`，与标签序列共用 `shape_seq_max_offset`
  换算门槛偏移；明细字段 `shape_below_ma` / `shape_above_ma` / `shape_lower_high` /
  `shape_higher_high` 每分钟写库，规则为空时纯观测。

配置项 `shape_ma_period`（默认 5）只影响日线序列读取长度，不影响其它编码。

**② 最高价低于前日次数（含当日）→ 次日超额**
