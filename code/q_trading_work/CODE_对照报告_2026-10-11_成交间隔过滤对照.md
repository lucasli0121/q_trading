# 成交间隔过滤：新增两个开关与实测对照

日期：2026-10-11
改动文件：`backtest/backtest_engine.py`、`backtest/main.py`、`tests/test_backtest.py`
数据快照：2026-10-11（服务端分钟 K）
命令基线：

```bash
python backtest/main.py --strategy volume --codes 000988 --frequency minute \
  --signal-window 25 --start "2026-07-21 09:30:00" --end "2026-10-08 15:00:00"
```

策略配置为新配置（`match.volume_mode: momentum` + `buy.volume_mode: reversion`）。

## 一、新增了两个机制，别混为一谈

### 1. 信号风暴过滤 `--storm-filter`（与实盘同语义）

复刻实盘 `StrategyWorkflow._save_trade_signal` 的判定，参数默认值同
`cfg/stock.cfg [signal_filter]`（10 分钟 / 2.0%）：

- 只对**同一天内、同一方向**的连续信号生效
- 距上一条**通过过滤**的信号不足 `--storm-time-gap-minutes` 分钟，**或**
  价格变化不足 `--storm-price-change-pct`，则抑制（两个条件都要达到才放行）
- 被抑制的信号不更新「上一条信号」，与实盘一致（实盘里它不写库）
- 默认**关闭**：实盘该过滤常开，但回测默认关掉才不会让历史回测数字失去可比性

**实测：在这组回测里它一次都没触发。** 原因是回测的成交序列天然是买、卖交替的
（有持仓才卖、无持仓才买），而这条过滤只比**同方向** —— 「卖完 1 分钟又买回」
是跨方向，直接放行。开关打开与关闭的结果逐项相同（36 笔 / −15.53%）。

所以它**解决不了**明细里那种高频进出。这是语义差别，不是实现没生效。

### 2. 成交间隔限制 `--min-trade-interval-minutes`（新增，0 = 关闭）

不分方向，直接限制**任意两次成交**之间的最小间隔。这才是「每次买卖间隔时间」
的语义，用来压「卖完又买回」。只在分钟频有意义；跨日第一次成交隔夜远超任何
合理阈值，天然放行，因此状态只需在日内维护。

## 二、实测对照

固定其余参数，只改成交间隔（单位：分钟）：

| 间隔 | 交易数 | 胜率 | 总收益 | 夏普 | 最大回撤 | 最终资金 |
| --- | --- | --- | --- | --- | --- | --- |
| 关闭 | **36** | 16.67% | **−15.53%** | −3.4068 | **21.59%** | 84,468.06 |
| 10 | 23 | 26.09% | −10.29% | −2.6935 | 16.92% | 89,706.33 |
| 30 | 9 | 22.22% | −8.81% | −3.1555 | 13.36% | 91,187.57 |
| 60 | **7** | 28.57% | **−5.63%** | **−2.2298** | **10.34%** | 94,367.03 |

趋势单调：间隔越长 → 交易越少 → 亏损越小、回撤越小。10 分钟（实盘 cfg 的默认值）
把 36 笔压到 23 笔，亏损从 −15.53% 收到 −10.29%，回撤从 21.59% 收到 16.92%。

这与上一轮对照报告的推断一致 —— 每笔往返成本约 0.5%，**交易频率直接决定成本总量**。

## 三、仍然不改变的事实

**四组全部亏损。** 60 分钟那组只剩 7 笔，样本小到没有统计意义；即便把间隔拉到
60 分钟，−5.63% 里仍有约 3.5% 能由 7 笔 × 0.5% 的成本解释，扣掉后信号本身的
贡献仍在零附近。

也就是说：**调间隔是在「少亏」而不是「转正」。** 要判断这套信号有没有可提取的
alpha，得先用零成本参数跑一次（`--buy-slip 0 --sell-slip 0 --fee-pct 0 --fee-low 0`），
把成本这一层剥掉再看。这一步还没做。

样本仍是单只股票（000988）、2.5 个月、满仓、分钟频，不能外推。

## 四、用法

```bash
# 与实盘同语义的风暴过滤（3.1 实测对本组无效果）
--storm-filter [--storm-time-gap-minutes 10] [--storm-price-change-pct 2.0]

# 限制任意两次成交的最小间隔
--min-trade-interval-minutes 30
```

两者默认都关闭，不传参数时回测行为与改动前完全一致。
