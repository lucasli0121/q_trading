## 一、结论

1. **回撤改成「卖出分值」后，成交量策略的收益与风险指标同时改善**：总收益 +8.69% → **+20.08%**，
   夏普 0.3302 → **0.6523**，最大回撤 17.01% → **16.57%**，最大单笔亏损 −15.19% → **−12.85%**。
2. **「不冻结」这一点得到实证**：开启与关闭回撤约束两版，**交易数完全相同（293）**，
   买点范围也完全相同（2026-07-29 ~ 2026-09-18）。回撤约束只改变了卖出时机，
   没有减少任何一笔开仓。
3. **仍未压到 −10%**（实际 16.57%）。根因是资金口径：权益按**成本**计价，浮亏不进入权益，
   回撤判定因而滞后于真实亏损 —— 触发清仓的那一天，被确认的亏损本身就已经越过阈值。
   这一条与阈值取 −5% 还是 −10% 无关，见第五节。
4. **胜率下降而收益上升**（51.19% → 43.00%）：提前卖出砍掉的是尾部亏损，不是提高单笔胜率。
   平均单笔收益由 +1.19% 变为 +0.17%，但亏损端被截短，净值反而高出 11 个百分点。
5. **同一快照下，默认方向 `reversion` 明显优于 `momentum`**：无回撤口径 +8.69% 对 −16.24%
   （293 笔对 17 笔）。默认值取 `reversion` 的依据在本轮更强。
6. 参数三处统一（类属性 / `cfg/strategy.yaml` / 服务端模板 `default_params`）由回归测试守住。

## 四、账户回撤作为卖出分值的实现

| 位置 | 实现 |
| --- | --- |
| 参数 | `risk.max_drawdown_pct`（%，负数生效，0 或正数关闭；基类默认 0.0，成交量策略默认 −10.0）<br>`risk.drawdown_score`（10 分制负值，默认 −6.0，与 `sell.max_score` 等值） |
| 策略 | `BaseStrategy._risk_drawdown_score()`：阈值已配置且账户回撤 ≤ 阈值时返回 `SELL_RISK_DRAWDOWN_SCORE`，否则 0.0<br>回撤值由 `BaseStrategy.set_account_drawdown()` 注入（策略只看得到单只股票行情，拿不到账户权益） |
| 成交量策略 | `_check_sell_conditions` 第 6 项：`score += self._risk_drawdown_score()`，reason 记「账户回撤 x% 达阈值 y%」 |
| 回测（日频） | `BacktestEngine._apply_drawdown_exit`：全部信号生成后重放，逐日判定，达阈值当日以收盘价卖出所有在持仓位（买入当日不卖），卖出日提前 |
| 回测（分钟频） | `_run_minute_inner` 每日开盘前注入账户回撤，由策略自身的卖出判定计分 |
| 实盘 | `StrategyWorkflow._refresh_account_drawdown` 在 `_process_bar` 调用策略前注入；`_buy_block_reason` **已移除**回撤条目（回撤不再阻断买入） |
| 口径 | 账户权益 = 初始资金 + 已实现盈利，与 `_compute_equity_curve`、`TradeManager._refresh_execution_metrics` 同源 |
| 峰值 | 实盘进程重启后由执行记录列表（`get_execution`）重建，避免以当前权益为峰值起步导致回撤被低估 |

卖出价与收益率由提前卖出当日的**收盘价**重新经 `_calc_trade_result` 计算（有效价含滑点与手续费，
不能按收盘价比例缩放），因此 `TradeResult` 新增了 `buy_price_raw` 字段保存原始买入价。

测试见 `tests/test_drawdown_breaker.py`（回撤口径、阈值边界含等号、未结算交易不计入、
买入当日不卖、收益率重算、不触发时结果不变、注入与告警去重、买入阻断不再含回撤）
与 `tests/strategy/test_volume_expansion_strategy.py`（`_risk_drawdown_score` 四个分支、
卖出分项端到端触发与不触发）。

## 五、为什么仍未压到 −10%

**根因：权益按成本计价，浮亏不进入权益。** `_compute_equity_curve` 把持仓按买入成本计价，
权益只在卖出结算时变动。于是「账户回撤」这个量在持仓浮亏期间**看不到亏损**，
只有平仓那一刻才一次性反映出来。

由此产生两个后果：

1. **判定天然滞后。** 触发日的判定依据是「已结算交易的权益」，而触发当天清仓时确认的亏损
   才第一次进入权益 —— 也就是说，回撤被观测到的时间点，就是它越过阈值的那一天。
   触发日的权益跳跃幅度 = 当日所有在持仓位的合计浮亏，可能远大于阈值。
2. **阈值越浅，触发越频繁，但不会更准。** 上一版实测已显示 −5% 与 −10% 给出完全相同的结果
   （拦住的是同一批信号）；本轮在同一份数据上改为「卖出」形态后，回撤仍在 16.57% 见顶。

要真正把组合回撤约束在 −10% 以内，必须让止损在**浮亏发生的过程中**介入，可选两条路：

- **个股止损按持有期价格路径判定**：日频回测里逐日检查「自买入价/持仓最高价的回撤」，
  触及即卖出，从源头限制单笔亏损幅度。这是当前日频框架缺失的能力（见第六节第 3 条）。
- **改用浮动权益口径**：每日按收盘价对持仓做市值重估，回撤判定基于浮动权益。回测可做，
  实盘需要每只持仓的最新价（分钟链路已有行情，但盘前/收盘后的判定需要额外口径）。

## 七、局限

1. **样本期短**：买点范围约 2026-07-29 ~ 2026-09-18，不足 40 个交易日，且 5 日持有窗口相互重叠。
   不足以判断长期表现；本报告 3.1 中「提前卖出提升收益」的结论尤其依赖该样本后期的下跌结构。
2. **数据快照不稳定**：服务端日K只保留约 3 个月且持续增长，`strong` 在两次快照之间从 +5.52% 变为 −9.16%。
   任何回测结论都必须标注快照时间与日期范围。
3. **日频回测不调用策略的卖出逻辑**：`_run_daily_inner` 只调 `before_trading` 与 `select`，
   卖出是「持有 5 日后收盘卖」加本报告新增的回撤提前卖出。策略里的
   `sell.drawdown_pct`、放量下跌、跌破均价、破支撑这些分项**在日频回测中不生效**，
   回测结论只反映「选股信号 + 固定持有 + 回撤提前卖出」，不代表策略实盘行为。
4. **未计基准**：`alpha` 恒为 0（基准关闭），跨策略对比是绝对收益对比。
5. **单笔手续费按 100 股估算**（`_calc_trade_result` 的 `quantity` 默认 100），对高价股会低估实际手续费占比。
6. **回撤提前卖出用当日收盘价成交**，未模拟盘中择时；实际触发时点与价格会有偏差。

## 九、答复与遗留

### 9.1 本轮答复的处理结果

1. **「把回撤超过 10% 作为一个卖出判断分值，不冻结账号」** — 已落地：
   新增 `risk.drawdown_score`（−6.0），`BaseStrategy._risk_drawdown_score()` 提供分值，
   成交量策略 `_check_sell_conditions` 第 6 项计入，实盘在 `_process_bar` 前注入回撤，
   `_buy_block_reason` 的回撤条目已删除；回测侧用 `_apply_drawdown_exit` 把
   「达阈值」落成「当日收盘卖出在持仓位」。交易数与买点完全不变验证了「不冻结」。
2. **服务端模板补 `drawdown_score`** — 已落地，模板 `6abb3227276f35f51ff8381c` 的
   `default_params.risk` 现含 `max_drawdown_pct` 与 `drawdown_score`。

### 9.2 遗留问题

1. **回撤未收敛到 −10%**（16.57%）。要达标必须让止损在浮亏过程中介入，
   两条路见第五节，需先确认选哪条。
2. **`momentum` 版回撤被放大**（19.96% → 27.48%）。这是「不冻结」语义的固有代价，
   是否需要给「回撤触发后的再次建仓」加冷却期或额外门槛，待定。
3. **日频回测与策略卖出逻辑脱节**。框架级现象，影响的不只是本策略。
4. **上一版报告 `momentum` 行（15 笔 / +1.57%）无法复现**。本轮同命令两次结果一致，
   `reversion` 两组数字与上一版完全相同，以本轮为准。
5. **服务端模板参数未做一致性校验**。本轮手工对齐了两个模板，但没有机制阻止将来再次分叉。
