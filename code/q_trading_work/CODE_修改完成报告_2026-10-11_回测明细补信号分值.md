# 回测明细补采信号分值

日期：2026-10-11
改动文件：`backtest/backtest_engine.py`、`dao/backtest_dao.py`、`tests/test_backtest.py`
状态：已改完并验证；回测结果数字与改动前逐项一致

## 一、问题

`bt_vol_000988.json` 的交易明细里只有价格与收益率，没有分值。

**不是导出时漏了，是回测引擎从未采集**。`TradeResult` 原本只有 8 个字段：

```python
code, strategy_name, buy_date, sell_date,
buy_price, sell_price, profit_pct, buy_price_raw
```

日频路径的问题更具体：`_check_daily_signal_at` 里写的是

```python
matched, _extra = strategy.is_match_strategy(window_data)
```

`extra` 收了 `score` / `star` 之后被整份丢弃，只在 `matched` 上做了判断。
分钟路径则是压根没从信号里取值。

## 二、改动

`TradeResult` 新增 4 个字段（默认 0.0）：

| 字段 | 含义 |
| --- | --- |
| `buy_score` | 建仓那根 K 线的信号综合分（10 分制） |
| `buy_star` | 对应星级（score/2 夹到 0~5） |
| `sell_score` | 平仓那根 K 线的信号综合分（负值） |
| `sell_star` | 对应星级 |

两条路径的填充方式不同：

- **日频**：`extra` 直接可用，取值写进 `TradeResult`。日频的卖出是「持有 N 日到期」
  的固定卖出，不产生信号 ⇒ `sell_score` / `sell_star` 恒为 0.0。
- **分钟**：买入时的分值**必须存进 `state` 随持仓跨日保留**。买入与卖出可能不在同一天
  （这次 36 笔里有 5 笔跨日），只在 SELL 分支现取 `extra` 会丢掉买入那根 K 线的分值。
  卖出时把买卖两侧一起传进 `_build_minute_trade`，平仓后清零。

`dao/backtest_dao.py::_trade_to_dict` 也要同步 —— 它是**显式白名单**（逐字段 `getattr`），
不是 `asdict`。不同步的话 `--output` 导出的 JSON 有分值、`--save` 写到服务端的没有。
反过来说，因为是白名单，加字段也不会让服务端 schema 报错。
