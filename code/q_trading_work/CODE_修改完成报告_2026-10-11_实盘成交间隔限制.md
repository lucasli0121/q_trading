# 实盘新增成交间隔限制（cfg 可配）

日期：2026-10-11
改动文件：`cfg/stock.cfg`、`cfg/stock.cfg.example`、`workflow/strategy_workflow.py`、
`tests/test_push_star_filter.py`
状态：已改完并验证；**默认 0（关闭）**，线上行为不变，填了分钟数才生效

## 一、做了什么

把回测侧的 `--min-trade-interval-minutes` 落到实盘，并放进 `cfg/stock.cfg` 的
`[signal_filter]` 节（与现有的信号风暴过滤参数同一节）：

```ini
[signal_filter]
price_change_threshold=2.0
time_gap_minutes=10
# ... 注释含回测实测数据 ...
min_trade_interval_minutes=0
```

- `0` = 关闭（**默认值，线上行为不变**）
- `N`（>0）= 距最近一条交易信号不足 N 分钟的信号被抑制

## 二、和现有的「信号风暴过滤」是什么关系

两条过滤都在 `_save_trade_signal` 里，共用「返回 False → 调用方不创建订单」这条退出路径，
但**语义相反，不能互相替代**：

| | 信号风暴过滤 | 成交间隔限制（新增） |
| --- | --- | --- |
| 配置项 | `price_change_threshold` + `time_gap_minutes` | `min_trade_interval_minutes` |
| 比较范围 | 只看**同方向**连续信号 | **不分方向** |
| 抑制条件 | 间隔不足 **或** 价格变化不足（两个都要达到才放行） | 间隔不足 |
| 作用 | 防同一方向重复下单 | 压「卖完又买回」这类高频进出 |
| 跨日 | 不判 | 不判（隔夜必然超阈值，等于自动放行） |

被抑制的信号**不写库** —— 与风暴过滤一致，因此它也不会成为下一次比较的「上一条信号」，
抑制会延续。

## 三、实现要点

- `_load_signal_filter_config()` 返回值从 2 元组改为 **3 元组**
  `(price_change_threshold, time_gap_minutes, min_trade_interval_minutes)`，
  缺省回退 `2.0 / 10 / 0.0`。只有一个调用点，没有测试锁定旧签名。
- `_save_trade_signal` 里在 `latest_any` 分支内**一次读出三个参数**给两个机制共用
  （原先只有风暴过滤用、且是惰性读），避免每条信号读两次配置文件。
- 间隔判定放在风暴过滤**之前**、独立于 `last_action == action` 那个分支 ——
  如果放进分支里就会退化成「只比同方向」，与回测的 `_trade_interval_blocked` 不一致。

## 四、怎么启用

改 `cfg/stock.cfg` 里那一行即可，改完重启服务（该配置在每次信号时读取，不是热更新项）。

回测实测（000988 分钟频）可作取值参考：

| 间隔 | 交易数 | 总收益 | 最大回撤 |
| --- | --- | --- | --- |
| 关闭 | 36 | −15.53% | 21.59% |
| 10 分钟 | 23 | −10.29% | 16.92% |
| 30 分钟 | 9 | −8.81% | 13.36% |
| 60 分钟 | 7 | −5.63% | 10.34% |

间隔越长亏损越小，但这几组**都是亏的** —— 调间隔是「少亏」不是「转正」。

间隔内抑制且不写库、超间隔放行、**跨方向也拦**（同时对照断言风暴过滤对反向信号放行）、

## 六、改配置时的注意

`cfg/stock.cfg` 用的是 **CRLF** 行尾（`stock.cfg.example` 是 LF）。脚本改这个文件时
必须沿用原换行风格，否则整个文件会显示成一整块 diff。
