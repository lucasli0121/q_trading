## 二、R1（阻断）：两个策略无法实例化

`SwingTradingStrategy.__init__` 与 `StrongReboundStrategy.__init__` 各补一个
`user_strategy_name` 形参，并继续往 `super().__init__()` 传。第二半是必需的：
只补签名不往下传，`self.user_strategy_name` 仍是空串，两个策略里以它为前缀的
日志与 `reason` 文本会变成以逗号开头的空名字。

顺带按答复调整了通知链路：`trade notify` 的 `recipient` 与 MQTT 载荷改用
`user_strategy_name`（`UserStrategyDao.name`），`strategy_name`（策略模板名）保留在
载荷里做兼容，未传时 `recipient` 回退到它。同一个模板下用户可能建多条策略，
只有用户自定义名能区分是哪一条发出的信号。为此 `StrategyState` 新增
`user_strategy_name` 字段，两个构造点（`_load_user_strategy`、`add_user_strategy`）填充，
`_instantiate_strategy` / `_build_strategy_instance` 各加一个透传参数。

实测：两个策略均可正常实例化，`self.user_strategy_name` 注入正确；
`tests/test_strategy_workflow.py` 原先 9 条 `TypeError` 失败全部消失。

## 三、R2、R3

R2 是符号写反：`score -= -2.0` 等价于 `+2.0`，把「价跌量增」计成了利多。同一份
12 根分钟线（价格逐根下跌、成交量逐根放大）：

```
改前  _check_volume_price_condition -> signal=BUY  score=1.0
改后  _check_volume_price_condition -> signal=SELL score=-3.0
价涨量增（同构数据）                -> signal=BUY  score=5.0   （未受影响）
```

R3 是空表崩溃：`InDaySRFactor.score_with_sr` 入口加 `sr_df` 空表与 `stock_array`
空数组保护，并补 `price <= 0 / NaN` 保护（否则 `price <= s3` 会假成立给出 +10）。
空表、空数组均返回 `0.0`。触发场景是新股上市首日、停牌复牌、日线回源失败
（服务端只留 3 个月），原实现每次抛 `IndexError` 后被外层吞掉，净效果是
该股票在这条策略下永不产生买卖信号，且每分钟刷一条 warning。

## 四、R4：波段策略的买入闸门（按答复保留设计）

按答复「这个设计是对的」，代码不动，把设计意图写进

## 五、R5：支撑/阻力档位

按答复的档位定义改成分档判定，支撑侧 `s[0]` 最低、`s[-1]` 最高：

| 条件 | 得分 |
| --- | --- |
| `n >= 1` 且 `price <= s[0]` | 10.0 |
| `n >= 3` 且 `price <= s[1]` | 7.5 |
| `n >= 2` 且 `price <= s[-1]` | 5.0 |

阻力侧按「越过几档」对称取值：`r[-1]` → −10.0、`r[-2]` → −7.5、`r[0]` → −5.0。
需要说明的是这里取的是 `r[-2]`（次高）而不是原实现的 `r[1]`（次低）：档位数等于 3
时两者是同一档，档位数 ≥ 4 时 `r[1]` 会让「只越过两档」也拿到 −7.5，与支撑侧
不再对称（支撑侧的 7.5 明确要求跌破三档）。若你要的是「从最低档往上数」的另一种
语义，把 `r[-2]` 换成 `r[1]` 即可，两种写法都已写在 docstring 里。

实测 4 档支撑 `[8.65, 9.25, 9.85, 10.45]`、4 档阻力 `[11.0, 11.6, 12.2, 12.8]`：

```
price= 8.0 -> 10.0    price= 9.0 ->  7.5    price=10.0 ->  5.0
price=12.9 -> -10.0   price=12.3 -> -7.5    price=11.7 -> -5.0   price=11.3 -> -5.0
```

1 档只出现 ±10，2 档出现 10/5/−5/−10，3 档起出现 ±7.5，与答复一致。另外补了
`price <= 0` 返回 0 的保护（原实现 `price <= s[0]` 对 0 或负数恒成立，会给 +10）。

## 六、R6：布林带轨道与档位

原实现 `r1/r2/r3 = 中轨 ± 2σ/4σ/6σ`。布林带窗口含当根价格，单点对中轨的偏离存在
上界 `sqrt(n-1)·σ`，n=5 时上界就是 2σ，因此 +4σ/+6σ 恒不可达，档位表实际只剩
±5 与 0。改按 1.0σ/1.5σ/2.0σ 定义（新增类常量 `R1_SIGMA`/`R2_SIGMA`/`R3_SIGMA`），
n >= 5 时三档全部可达；`calculate()` 返回值新增 `sigma` 列，便于核对。

零波动窗口（一字板、长时间无成交，σ=0）时三轨与中轨重合，原实现下
`price >= r3`（即 `price >= 中轨`）恒成立，score 恒 −10，涨停一字板会被判成
极度超买而触发卖出。现在 σ <= 0 直接返回 0.0。实测 n=5 下 ±10/±7.5/±5/0 六档
全部可达，一字板返回 0.0。

## 七、R7：关于 MultiTrendFactor 的尺度

**先回答提问：出现在 `strong_rebound_strategy`，`swing_trading_strategy` 不用这个因子。**
强反弹策略有两处调用，选股时算趋势分（`is_match_strategy`）、盘中算趋势分
（`_check_buy_conditions`），两处都受这次权重重标影响。

**报告里「满分由 10 变成 7」这个数字要更正。** 权重重标前后都是 10 分制：

| | 改前 | 改后 |
| --- | --- | --- |
| 权重 | 2 / 2 / 2 / 1 / 1，合计 8 | 3 / 3 / 3 / 0.5 / 0.5，合计 10 |
| 返回值 | `score / 8 * 10` | `score`（不再归一化） |
| 名义满分 | 10.0 | 10.0 |
| 各分项占比 | 25% / 25% / 25% / 12.5% / 12.5% | 30% / 30% / 30% / 5% / 5% |

同一段数据逐根截断喂入（实测）：

```
n= 10 根 -> 4.0   NaN: adx / macd_dif / macd_hist
n= 20 根 -> 7.0   NaN: macd_dif / macd_hist
n= 34 根 -> 7.0   无 NaN
```

改前同口径值为 7.5，改后 7.0，差 0.5 分。真正的变化在两处：一是次要项（VWAP、前高）
的占比从 25% 压到 10%，二是 MACD 那一项占 30% 却在实盘拿不到。MACD 需要
26+9−1=34 根才有值，而选股与回测都只取 20 根日线，`macd_hist` 恒为 NaN
（`NaN > 0` 为 False，不进计分分支，所以是静默丢分而不是算错），这使得 20 根窗口下
的可达上限只有 `3 + 3 + 0.5 + 0.5 = 7.0`。阈值 `UP_TREND_SCORE = 6.0` 本身没有失效
（MA5>MA10 与 ADX 同时成立恰好 6.0），但它等于可达上限的 86%（改前是 7.5 的 80%），
没有余量，靠 VWAP 或前高补不上缺口。

本轮不改权重与阈值，因为「趋势分满分应该是多少」是产品决策，且改动会直接影响
已上线策略的选股结果。已把权重表、「MACD 需 34 根」和可达性写进类 docstring，
并把各分项抽出类常量（`MA_SCORE`/`MACD_SCORE`/`ADX_SCORE`/`VWAP_SCORE`/
`PREV_HIGH_SCORE`/`MAX_SCORE`），改动任一权重时能一眼看到刻度关系。两个可选修法
见第十一节。

## 八、R8、R9

R8 按答复改成「成交量为主要权重、趋势为辅」：两侧各自归一化到 0~1 后加权
（成交量 0.7、趋势 0.3），再乘 10 回到 10 分制。

```
avg_score = (volume_score / 5.5 * 0.7 + trend_score / 10 * 0.3) * 10
```

读的是 `reason`），并在卖出分支补 `extra["star"]`。

## 九、R10、R11

R10：`_get_highest_since_buy` 的 docstring 改成实际口径（`end` 直接取当前行情时间，
故意不做上一交易日换算，因为只需要最近一段区间的最高点），日K查询接入二级缓存：

- key `hprice:{code}:{buy_date}:{day}`，TTL 6 小时，内存快照优先、Redis 兜底，
  Redis 不可用时自动降级（回测本来就关 Redis）；
- `save_highest_price` 只增不减（同日区间只会向右延伸），并发写入不会把高值覆盖成低值；
- `clear_minute_day` 同步清理该类的内存快照；未命中返回 0.0（日K最高价恒为正，
  0 可以安全表示「没有缓存」）。

实时链路下未持仓股票每分钟都会走一遍卖出判定，池内 300 只即每分钟 300 次日K请求，
加缓存后同日同区间只发一次。

R11：`VwapFactor.calculate` 改成 `df.tail(self.days)`，`days` 真正生效
（配置里的 `vwap_minutes_limit` 此前完全没作用，算出来是当日累计 VWAP），
并去掉 `round(result, 2)`（先取整再算百分比，对低价股会引入固定相对误差）。
实测 `days = 0 / 3 / 5` 分别得到 15.0 / 20.0 / 20.0。

## 十、R12~R16

R12：`score()` 的 docstring 改为 10 分制维度表（连续放大 2.0、量比 2.0、斜率 1.0、
量价配合 2.0、OBV 1.0、突破 2.0，合计 10.0），并把量比档位重标（2.0/1.6/1.2/0.6）、
OBV 与斜率降为 1.0，使之与 `signal` 阈值同刻度。返回值仍保持 dict（调用方需要
`reason` 明细），但在 docstring 里写明契约：不能写成 `score += factor.score(df)`，
必须取 `["score"]` 字段。条件1 的 `else: score = 0.0` 改为局部变量
`consecutive_score`，语义仍是「连续放量不足两天时该项不计分」，但不会再把前面
已累计的分整体清零。数据不足时也返回结构完整的字典，不再是裸 `0.0`。

R13：在基类抽出三个共用方法，两个策略都改用它，避免阈值在四处各写一份。

- `price_limit_pct(code, name)`：名称含 ST → 5%，代码前缀 300/301/302/688/689 → 20%，
  其余 → 10%；
- `_near_price_limit_pct(code, name, margin)`：涨跌停幅度减余量，最低 1.0；
- `_change_percent(stock_data, price, preclose)`：`change_percent` 是小数比率，
  统一乘 100；字段缺失、为 0 或非数字时用昨收自算；`preclose <= 0` 不做除法。

四个判定点（两个策略的买入与卖出）都改为 `abs(chg_percent) >= near_limit`，
即**涨停与跌停两个方向都挡**，与原实现 `abs(...) >= 9.5` 的方向集合一致，
只把阈值改成按板块推算（波段留 1 个百分点余量，强反弹买入侧留 2）。实测：
主板 ±9% 挡下、创业板 ±9% 放行、ST +4.1% 挡下。

R14：删掉 `strong_rebound` 的 3 个未使用导入（`HighDeclineFactor`、`KlineSRFactor`、
`VolumeExpansionFactor`），`swing` 的 `low_price` 换成真正要用的 `stock_name`。
原先「算了不用」的 `star` 已由 R15 贯通到信号记录，不再是空转。

R15：`TradeSignalApi.add()` 新增 `score`/`star` 参数（`round(score, 2)`、
`round(star, 1)`，与 `dao/trade_signal_dao.py` 的字段注释一致），
`_save_trade_signal` 从 `extra` 解析这两个字段（带类型兜底）、透传给 `add()`，
并写进 MQTT 载荷与日志。买入侧的 `star` 由综合分折算（`avg_score / 2`，夹到 0~5），
卖出侧由 `-score / 2` 折算。

R16：按答复「已修改 q_data_proxy 的问题」，本端只补注释：在 `_change_percent`
的 docstring 里写明「`change_percent` 是小数比率」这一量纲依赖，并提示换实时数据源时
必须重新核对，否则会退化成「任何下跌都不买、任何上涨都不卖」。
