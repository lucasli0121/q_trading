## 三、P0-26：回退手续费口径（重要）

**决策**：服务端未对历史持仓回填 `fee`，且费用计算本身无误 → **恢复旧口径**
`cost_price = (成交金额 + 买入手续费) / 数量`。

### 3.1 改动清单（三处口径必须一致，已同步）

| 位置 | 改前（P0-26 引入） | 改后（恢复旧口径） |
|---|---|---|
| `TradeManager._apply_order_to_positions` | 成本价=纯成交价，手续费单独累计到 `fee`；卖出按比例释放并返回 | **成本价含手续费**；加仓加权同样含本次费；卖出不改变成本价；不再返回释放额 |
| `TradeManager._refresh_execution_metrics` | `已实现收益 += 卖出盈亏 − 释放的买入费`<br>持仓盈亏 `=(现价−成本价)×数量 − fee`<br>`剩余资金 = 初始 + 已实现盈利 − Σ(数量×成本价) − Σfee` | `已实现收益 += 卖出盈亏`<br>持仓盈亏 `=(现价−成本价)×数量`<br>`剩余资金 = 初始 + 已实现盈利 − Σ(数量×成本价)` |
| `StrategyWorkflow._calc_available_cash` | 同上去掉 `total_fee` 项 | 同步回退 |

### 3.2 为什么这样是自洽的

- 卖出订单的盈亏由 `TradeManager.execute_order` 计算：`收入 − 成本价×数量 − 卖出费`。
  成本价含买入费 ⇒ 该式**同时覆盖买卖两次费用**，无需再单独冲减。
- 持仓浮盈 `(现价 − 成本价) × 数量` 天然含买入费。
- 剩余资金只扣 `数量×成本价`，**不会再重复扣一次手续费**——这点已用测试钉住
  （若重复扣会算成 8990 而不是 8995）。

### 3.3 `fee` 字段的定位（保留但降级）

- 服务端已支持该字段 → 继续**写入**，含义收敛为「该持仓累计买入手续费」，**仅审计/展示用**。
- 卖出时按剩余比例结转（`fee × 新数量/旧数量`），全清仓时随持仓一起删除。
- 代码与文档已明确标注：**不参与任何资金/盈亏计算**（费用已含在 `cost_price` 里），避免后人误用导致重复计费。

### 3.4 顺带加固

- `_apply_order_to_positions` 补 `new_qty <= 0` 早退与除零防护（原实现在极端参数下会 `ZeroDivisionError`）。

> 结论：**本次回退后，历史数据与新增数据的成本价口径完全一致**，不存在新旧混排的展示差异，
> 也**不需要任何数据修正脚本**。
