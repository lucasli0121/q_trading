## 凌晨两点，你还在等一个邮件

你的策略在服务器上跑着。凌晨两点，某个信号触发了，仓位变了。你要么一直盯着屏幕，要么赌一封邮件会准时到。

第二天早上你打开邮箱，看到三封未读：一封说"策略运行中"，一封说"恭喜，你的收益是 -3.7%"，一封说"某个指标缺失"。你想知道今天到底该不该停掉这个策略，但这些邮件什么都告诉你不了。

QTrade 的 Web 客户端要解决的就是这件事：**把跑在后台的策略，变成一个可以随时打开、随时看明白、随时动手的界面。**

## 一、它是什么

QTrade 是一套跑在 A 股的量化交易系统，分三层：

- **q_trading_work**：策略引擎。定时取数、算信号、下单。这部分决定"赚不赚钱"。
- **q_trading_server**：数据与接口层。FastAPI + MongoDB + Redis，对外提供行情、策略、订单、用户等接口。
- **q_trading_cli**：你正在用的这个。NiceGUI 写的 Web 客户端，负责"看"和"控"。

第三层是本文的主角。它的定位很明确：**不碰数据库、不跑策略，只做展示与干预。**

这个边界带来的直接好处是，客户端可以独立部署、独立发版、独立回滚。改一个界面文案不需要动交易引擎，策略引擎半夜崩了也不影响你查历史数据。反过来，客户端出了 bug 顶多看到的数据不对，不会误下单。

技术上它是一套相当克制的设计：

- Python 3.12，NiceGUI 3.x（跑在 FastAPI + uvicorn 上）
- 所有数据访问走 httpx 调后端 REST，代码里没有一行 `pymongo`
- 实时信号走 MQTT（paho-mqtt，双向 TLS 证书）
- 主题、限流、路由、收益口径各有一个单一入口

代码规模上，页面层 9561 行、接口层 2503 行、组件层 2084 行，测试 6393 行。

## 二、你什么时候会打开它

### 盘前：今天买什么

打开"策略选股"，顶部 Tab 是你的各个策略实例，点进去看当天选出的股票、现价、涨跌幅。**红色是涨，绿色是跌**，跟你在所有 A 股软件里看到的一致，不用切换视觉习惯。

同时去"股票池"看一眼池子状态。统计栏会告诉你有几个自动更新池、几个静态池，池子同步出问题的话，选股结果自然不对。

### 盘中：出了什么信号，能不能停

"策略监控"页是信息密度最高的一屏。上面四张统计卡给全局信号概览，中间是策略卡片区（横向滚动），每张卡显示这个策略已运行多久、当前持仓数、浮动盈亏。最下面是实时信号日志表：

```
时间 | 策略 | 股票代码 | 信号类型 | 成交价格 | 盈亏率 | 原因
```

股票代码下面带股票名称，不用再切到行情软件去对代码。信号是 MQTT 推过来的，不用手动刷新。

**最重要的一行操作在策略卡片上**：看到某个策略在连续发 undesired 信号，直接在卡片上启停，状态立刻生效。状态是全局的，你在列表页的编辑对话框里改、在监控卡片上改，改的是同一个东西。

### 盘后：这一周到底怎么样

仪表盘上的"系统累计收益"曲线给出这段时间的整体表现。右上角可以下拉选一个具体策略，叠加一条琥珀色副线做对比，两条线的日期取并集，某天没有数据就断线，不补 0 假装有值。

这里有一个口径细节值得说明。**曲线上的每个点是各用户策略收益率的平均值，收益为 0 的策略既不进分子也不占分母。** 这不是偷懒，是业务上必须这么算：一个刚创建还没开仓的策略如果参与平均，会把整条曲线拉向 0，看起来像"系统在亏钱"，其实只是分母里多了一个空账户。

末点（代表"当前"）单独覆盖成含浮动盈亏的口径：`(已实现盈亏 + 持仓浮盈) / 初始资金`。历史点做不到这一点，因为当时的持仓对应的实时价无法回溯。

### 离开屏幕之后

"个人喜好"页可以开企业微信推送和短信推送，各配一个**推送星级**滑块：买入信号、卖出信号各一个，范围 0 到 5.0 星，步长 0.5。**0 表示不限**，拉到 4.0 就只推 4 星以上的信号。

低质量信号刷屏是监控系统最常见的死法。星级阈值让通知的密度回到可控范围。

## 三、它给谁用

**主要用户是自建策略的量化交易者。** 典型画像：懂 Python 和 K 线，用现成模板（强势反弹、趋势追踪、网格交易、多因子选股）跑实盘，但不想每次查数据都开终端 curl 接口。他们要的是"策略跑得怎么样、我该管还是该放"。

**次要用户是跟着信号做决策的人。** 他们不改参数，只关心今天出了什么信号、选出了哪几只票。对应的是监控页和选股页这两屏。

**不适合的场景要说明白**：需要自己写因子代码、需要 tick 级数据、或者需要 24×7 无人值守盯盘——那是策略引擎（q_trading_work）和小程序端的活，不是 Web 客户端的。

移动端由**微信小程序**承担，接的是同一套后端 API。在路上用手机看一眼今日信号和选股结果，不需要开电脑。

## 四、功能地图

九个页面，侧边栏直达：

| 页面 | 路径 | 作用 |
|---|---|---|
| 仪表盘 | `/` | 收益曲线、策略统计、今日信号、近期运行状态、系统消息 |
| 策略列表 | `/strategies` | 创建/编辑策略、启停、看持仓与订单明细、进回测记录 |
| 策略监控 | `/strategy-monitor` | 策略卡片 + 实时信号流 + 卡片内启停 |
| 策略选股 | `/strategy-select` | 按策略查当天选股结果 |
| 回测记录 | `/strategy-backtest` | 回测指标 + 逐笔成交明细 |
| 股票池 | `/stock-pools` | 池子管理、自动更新状态 |
| 行情 | `/stock-quotes` | 按池子分 Tab 看行情 |
| 个人喜好 | `/settings-preferences` | 主题、推送通道、推送星级 |
| 黑名单 | `/settings-blacklist` | 批量排除股票并记录原因 |

再单独一个登录页 `/login`，支持用户名、邮箱、手机号任一 + 密码登录，也支持注册。

### 几个做得比较细的地方

**创建策略是一个表单，不是向导。** 选模板卡片（横向滑动）→ 配股票池 → 填参数 → 勾"立即运行"。"立即运行"默认勾上，勾了就是以 running 状态创建，不用创建完再去列表页改一遍状态。

**回测记录页的返回按钮跟随入口。** 从监控页点进来，返回就回监控页；从列表页点进来，返回就回列表页，连侧边栏高亮也跟着变。这个细节看着小，但少点一次"我要回哪儿"。

**持仓盈亏是现算的。** 接口返回的 `profit_rate` / `profit_amount` 是**成交时点的快照**，买入时写入、卖出时才重算。页面如果直接显示它，看到的就是一个过期数字。所以页面一律用 `成本价 + 数量 + 实时价` 现推，缺实时价就显示 `--`，不拿旧值糊弄。

**状态选项不会静默改掉你的设置。** 后端的 `error` 是故障态、不能选，但如果某个策略当前恰好处于 error，编辑对话框会临时把它补进下拉选项——否则会出现"下拉显示空白但保存时写回旧值"的静默改配置。

## 五、体验上的几个决定

**颜色全部走设计令牌。** `colors/theme.py` 里一份 `TOKENS` 字典，一个变量名对应深浅两套值。切换主题是会话级的、即时生效、零重渲染。图表配色单独走一套 API，因为 ECharts 画在 canvas 上，读不到 CSS 变量。

**数字错误会说人话。** 后端返回 4xx 时会提取 `detail` 字段显示，而不是甩一串 `Client error '409 Conflict' for url ...`。用户名重复会明确告诉你用户名已存在。401 会弹确认框跳登录页。

**刷新策略表不会打爆后端。** 行情 30 秒 TTL、策略表 60 秒会话节流，信号靠推送。**收益曲线不做无意义的定时刷新**——只在首次构建、切换周期、切换对比策略时重算。

**深色模式是即时保存的。** 不是"改了要记得点保存"，是拨一下就落库。

## 六、它是怎么被验证的

这类界面最怕的是"看着对、数字错"。所以这个项目的自检分两层。

**第一层是桩冒烟。** 把 nicegui、app_context、core 这些依赖替成桩，然后**真跑一次页面入口函数**，断言它不抛异常、DOM 结构符合预期。六个页面各有一份这样的检查（概要页 115 项、监控页 82 项、回测页 91 项、列表对话框 64 项、喜好页 30 项），加一个跨项目的属性级审计。

**第二层是反向验证。** 把源码指向一份"故意改坏"的副本，再跑检查，**要求它必须报错**。比如"当天多条记录相加"这种曾经真实发生过的口径错误，被写成了 7 条专门的用例守着。目前 101 个改坏用例全部被抓到。这套方法的价值在于：它验证的不是"现在是对的"，而是"以后改坏了会被立刻发现"。

**第三层是真机对账。** 涉及"页面上数字对不对"的结论，必须起真实实例、连真实后端、读渲染后的图表数据，再和独立复算逐点比对。桩检查只能证明不抛异常，证明不了数字对。

## 最后

量化交易真正的瓶颈通常不在算信号，而在**看懂并干预**：收益是多少、哪些策略该停、今天出了什么信号、浮盈是正是负。

QTrade 把这四件事收进一个登录后即用的界面，并且刻意不碰交易本身。**前端可以随便改，引擎必须稳。** 这条边界是这个系统能长期跑下去的前提。

如果你也在跑策略，欢迎打开看看。
