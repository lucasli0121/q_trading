# QTrade 策略交易系统 — 页面操作文档

| 项目 | 说明 |
| --- | --- |
| 文档版本 | v1.0 |
| 编写日期 | 2026-09-16 |
| 适用代码版本 | `q_trading_cli`（路由表以 `core/routes.py` 为准） |
| 适用对象 | 使用 Web 端管理策略、股票池与行情的使用人员 |

---

## 1. 系统概述

QTrade 是一个股票量化策略的 Web 管理端，自身不产生行情数据，全部数据通过调用后端 API 获取：

- **策略模板 / 用户策略**：策略列表、参数、状态、持仓、订单、运行日志
- **交易信号**：由 MQTT 实时推送，前端在内存中滚动保留 **最近 12 小时**
- **股票池**：自动同步 / 条件筛选 / 系统自动 / 手动维护四类
- **行情**：实时行情、日 K、分时、选股结果

界面为深色主题，左侧固定导航抽屉（宽 256px），右侧为内容区。

## 2. 访问与登录

### 2.1 登录页 `/login`

页面为一张卡片，顶部是品牌标识 **QTrade**，其下为「登录 / 注册」切换标签。

卡片横向位置：**卡片中心落在窗口宽度的黄金分割点（61.8%）处**，即 `padding-left = calc(23.6% + 1rem)`、`padding-right = 1rem`（见 `pages/login_page.py` 的 `.login-viewport`）。窄屏（≤767px）自动回退为水平居中，以免卡片被压到右缘。
背景为量化终端风格的动态层（网格 / 辉光 / QTRADE 水印 / K 线蜡烛粒子），背景层在卡片之下，卡片为毛玻璃以透出背景。

| 元素 | 说明 |
| --- | --- |
| 登录 / 注册标签 | 点击切换两种表单，输入内容会清空 |
| 用户名 / 邮箱 / 手机号 | 三者任一均可；在输入框内按 **Enter** 直接提交 |
| 密码 | 带「显示 / 隐藏」小眼睛；按 **Enter** 直接提交 |
| 记住我 | 默认勾选（当前仅作界面展示，登录态本身由浏览器会话维持） |
| 忘记密码？ | 点击后提示「请联系管理员重置密码」 |
| 登 录 | 主按钮，提交登录 |
| 还没有账号？立即注册 | 切换到注册表单 |

**登录步骤**

1. 打开系统地址，未登录时会被自动引导到登录页。
2. 输入账号（用户名 / 邮箱 / 手机号）与密码。
3. 点击「登 录」或按 Enter。
4. 成功后右上角提示 **登录成功**，并跳转到登录前想访问的页面；若此前没有明确目标页，则回到仪表盘。

**反馈提示**

| 提示 | 原因 |
| --- | --- |
| 登录失败: … | 账号或密码错误等业务错误 |
| 网络错误: … | 后端不可达或超时 |

### 2.2 注册页（登录页内切换）

| 字段 | 校验规则 |
| --- | --- |
| 用户名 | 必填，4–16 位字母或数字 |
| 邮箱 | 必填 |
| 手机号 | 必填 |
| 密码 | 至少 8 位，且需包含字母和数字 |
| 确认密码 | 必须与密码一致 |

**注册步骤**

1. 在登录页点击「注册」标签。
2. 依次填写上述 5 个字段。
3. 点击「注 册」。
4. 注册成功后系统会**自动登录**并跳转目标页；若自动登录失败，则切回登录表单让用户手动登录。

**校验提示**：`用户名应为4-16位字母或数字` / `密码至少8位，含字母和数字` / `两次输入的密码不一致`。

### 2.3 登录态与自动登出

- 页面每秒做一次登录态心跳检测。若后台请求返回 **401**（token 过期或被踢下线），会话被清除，页面**自动跳转登录页**。
- 退出登录：点击侧边栏左下角的 **⋮** → 「退出登录」。退出后会清空当前会话并回到首页。

> ⚠️ 退出登录只清理**当前浏览器会话**，不会影响其他用户的数据。

## 4. 通用交互约定

### 4.1 涨跌颜色（A 股惯例）

| 含义 | 颜色 |
| --- | --- |
| 上涨 / 买入 | **红色** |
| 下跌 / 卖出 | **绿色** |
| 持平 | 常规文字色 |

该约定贯穿行情表、信号日志、盈亏列、K 线图等所有涉及涨跌的位置。

### 4.2 策略状态徽标

| 状态值 | 显示文本 | 颜色 |
| --- | --- | --- |
| `running` | 运行中（带呼吸圆点） | 绿 |
| `stopped` | 已停止 | 灰 |
| `paused` | 已暂停 | 黄 |
| `error` | 异常 | 红 |

> 状态的两处修改入口：**策略监控页**卡片上的「启动 / 暂停 / 停止」按钮；**策略列表页**编辑对话框的「运行状态」下拉。
> 新建策略时由创建对话框的「**立即运行**」勾选框决定初始状态（默认勾选 → 运行中）。
> `error` 是服务端判定的故障态，**不作为用户可选项**（编辑时若当前就是异常，该项会临时出现在下拉里以便保持原状）。

### 4.3 页面反馈与加载

- 所有业务操作结果通过**右上角浮层提示**（notify）返回，颜色语义：绿色=成功、红色=失败、黄色=警告、蓝色=信息。
- 表格类页面在加载时显示**转圈动画 + 文案**（如「正在加载选股行情...」「正在加载行情数据...」）。
- 空数据统一显示灰色图标 + 文案（如「暂无交易信号」「暂无策略数据」「黑名单为空」）。

### 4.4 页面异常

若某个页面内容渲染失败，页面不会白屏，而是显示红色错误图标 + 「页面加载失败」+ 具体错误信息，左侧导航仍可用，可切换到其他页面。

## 5. 页面详细操作

### 5.1 仪表盘 `/`

首页，用于快速掌握整体运行状况。

**顶部标题栏**：页面标题「仪表盘」、右侧绿色圆点 +「交易系统运行中」状态文案、以及**通知铃铛**。

- 有新的系统消息时，铃铛右上角出现红色角标。
- 点击铃铛 → 弹出「系统消息」对话框，逐条列出**标题 / 时间 / 内容**（按时间展示，内容保留换行）。
- 打开对话框即视为已读，红色角标消失。
- 无消息时显示「暂无系统消息」。

> 通知铃铛**仅存在于仪表盘**，其他页面顶栏为各页自建，不含铃铛。

**统计卡片（4 个）**

| 卡片 | 数值含义 | 角标 |
| --- | --- | --- |
| 策略总数 | 当前用户的用户策略条数 | `+N 本月`（本月新增） |
| 运行中策略 | 状态为 `running` 的策略数 | 运行平稳 |
| 股票池数量 | 后端返回的股票池总数 | — |
| 今日信号数 | 今日 0 点起的信号条数 | 今日活跃 / 暂无 |

**系统累计收益概览**（左侧 2/3 宽）

- 折线图，时间范围可切换：**7天 / 30天 / 1年**（点击标签切换）。
- **系统总收益曲线**（蓝色，带渐变面积）：按 `update_time` 落到日期，每个数据点取当天
  **全部**执行记录 `current_return_rate` 的**算术平均**（同一天多条记录直接平均，不按策略去重，
  见 `core/holdings.py::daily_average_rates`）。该字段只含**已实现**盈利
  （后端 `trade/manager.py` 的定义）。
- **末点**（代表「当前」）单独覆盖：取各用户策略的最新一条执行记录，用
  `(current_profit + 持仓未实现盈亏) / base_amount` 算出含浮盈的收益率后取平均
  （`core/holdings.py::average_current_rate_pct`）。历史记录对应的是当时的持仓，
  实时价无法回溯，所以历史段不含浮盈。
  缺实时价的策略**退化为它的 `current_return_rate`**，不从平均里剔除——剔除会改变分母，
  曲线末点会莫名跳变。
- **单策略对比曲线**：右上角「对比策略」下拉框选中某个用户策略后追加一条（琥珀色、无线宽面积、
  更细）。数据是同一批记录按 `user_strategy_id` 过滤后的当日平均，末点同样叠加该策略浮盈。
  两条曲线的日期取**并集**，各自缺失的日期留空断线（不补 0）。
  所选策略在该时间范围内没有记录时，不画这条线，并在图下方给出提示。
  下拉框默认不选（只画系统总收益）；带搜索、可清空。
- **取数**：先用全量执行记录确定窗口基准（**最后一个数据点**，不是今天）与末点，
  再调 `GET /api/user_strategy/executions/range` 按窗口（`最后数据点 − N 天` 到 `最后数据点`）
  做服务端过滤取曲线数据点。全量与实时行情各按 30 秒 TTL 缓存。
- 窗口基准取最后数据点而非今天：策略没交易就没有新记录，以今天为基准时久未交易的策略会画出空图。
- 末点算不出时（无执行记录、或该策略连 `current_return_rate` 都缺）不覆盖。

**近期运行状态**（右侧 1/3 宽）

- 展示**最近 4 条**信号活动，每条为：策略名称、`触发买入信号: 股票代码`（买入红 / 卖出绿）、时间。
- **策略名称取用户策略名称** `user_strategy.name`，回退链为 用户策略名 → 策略模板名 → `--`。
  信号里的 `strategy_id` 是**策略模板 ID**，同一模板下建了多个用户策略时会显示成同一个名字，因此按 `user_strategy_id` 归并。
- 无数据显示「暂无信号活动」。
- 底部「查看全部活动」按钮 → 跳转策略监控页。

**近期更新策略表**

- 最多显示 **5 行**，列为：策略名称 / 类型 / 创建日期 / 状态 / 收益率。
- 策略名称优先取用户自定义名称，无则回退策略模板名称。
- **收益率列口径**：取该策略**最新一条**执行记录，
  值 = `(current_profit + 持仓未实现盈亏) / initial_amount × 100`
  （含浮动盈亏，与策略监控页卡片「浮动盈亏」同一套算法，实现在 `core/holdings.py`）。
  该列用**全量**执行记录（需取「每个策略最新一条」，按时间范围查会漏掉窗口外的策略）。
- 列名不带周期后缀（2026-09-23 用户确定）：该列展示的是**最新收益率**，不是 N 天窗口内的收益，
  写「收益率 (30d)」名实不符。资金曲线上的 7天/30天/1年 是**曲线**的窗口，与本列无关。
  `PositionItem` 里的 `profit_rate` / `profit_amount` 是**成交时点快照**，不参与计算。
- 收益率算不出时显示 `-`：没有执行记录、缺 `current_profit`、或持仓缺实时价
  （**不退回**已实现口径、也不用部分持仓凑数）；有值时按涨红跌绿显示，保留 1 位小数。
- 右上角「管理所有策略」按钮 → 跳转策略监控页。

**自动刷新**：今日信号数每 3 秒刷新；通知角标每 10 秒检查；**近期更新策略表**每 60 秒刷新。
⚠ **累计收益图没有定时刷新**——只在卡片构建（页面加载）、点击 7天/30天/1年、切换对比策略时重算，
所以末点那个「实时」只在这些时刻成立。数据无变化时不会重建表格（避免闪屏）。
实时行情与全量执行记录各按 30 秒 TTL 缓存，收益图与策略表共用一份
（页面加载只打一次全量请求 + 一次行情接口）。切换对比策略复用已查回的窗口数据，不重复请求。

### 5.2 策略列表 `/strategies`

管理与查看用户策略的主页面。

**标题栏**：左侧「策略列表」，右侧蓝色「**创建策略**」按钮（带 + 图标）。

**筛选栏**（一行，可换行）

| 控件 | 作用 |
| --- | --- |
| 搜索框 | 按策略名称 / 描述模糊匹配，输入停止 300ms 后自动生效，可一键清空 |
| 类型下拉 | 选项为「全部类型」+ 后端返回的策略类型列表 |
| 状态下拉 | 全部状态 / 运行中 / 已停止 / 已暂停 / 异常 |
| 重置 | 清空搜索、类型、状态三项条件，并回到第 1 页 |

> 任一筛选条件变化都会自动把页码重置到第 1 页。

**策略表格**

| 列 | 内容 |
| --- | --- |
| 策略名称 | 自定义名称 + 下方灰色小字描述（过长省略） |
| 类型 | 策略模板类型 |
| 总收益 | 涨红跌绿 |
| 状态 | 状态徽标；运行中额外带绿色呼吸圆点 |
| 最近信号 | 形如 `买入 600519`（买入红 / 卖出绿），无信号显示 `-` |
| 操作 | 「回测记录」图标（跳转策略回测记录页）+ 铅笔图标（编辑） |

**分页**：每页 10 条，页脚显示「显示第 X-Y 条结果，共 N 条」以及「上一页 / 页码 / 下一页」，首末页自动置灰。

**交互**

- **点击任意一行** → 在下方展开该策略的**详情面板**。
- 点击行尾铅笔图标 → 打开**编辑策略**对话框（不展开详情）。
- 数据每次渲染都会拉取最新的每个策略最近一条信号，因此「最近信号」列始终是最新值。

**详情面板**

标题为「{策略名称} — 策略详情」，右上角 × 关闭。下方三个标签页：

| 标签 | 列 |
| --- | --- |
| 持仓信息 | 股票代码 / 股票名称 / 持仓数量 / 成本价 / 现价 / 盈亏 |
| 订单明细 | 日期 / 股票 / 方向 / 数量 / 价格 / 成交额 |
| 运行日志 | 逐行的「时间 [级别] 内容」文本 |

- 切换标签只渲染当前页内容，不重新加载整页。
- 订单明细取**当前持仓股票**、方向为**买入**的最新订单记录。
- 无数据时显示「暂无持仓 / 暂无订单 / 暂无运行日志」等空态提示。

**「盈亏」列的口径与格式**

| 项 | 说明 |
| --- | --- |
| 格式 | `收益率(收益额)`，形如 `+10.00%(2000.00)`；收益率带正负号、两位小数，金额取绝对值 + 两位小数 |
| 颜色 | 盈利红色 / 亏损绿色（A 股惯例，见 4.1 节） |
| 现价 | 取 `market_api.get_real_time()` 的**实时价** |
| 收益率 | `(现价 − 成本价) / 成本价 × 100`；成本价为 0 时无定义，显示 `+0.00%` |
| 收益额 | `(现价 − 成本价) × 持仓数量` |
| 缺实时价 | 现价与盈亏一并显示 `--`（停牌 / 行情接口失败 / 代码不在返回里） |

- 收益率与收益额**必须用实时价与成本价现算**，不得读 `PositionItem.profit_rate` / `profit_amount`。
  这两个字段是**成交时点值**：买入时写入、持仓期间后端不参与计算、直到卖出那一刻才重算。
  也就是说持仓期间读它，读到的是「买入时的收益」，与当前浮动盈亏无关；
  持仓期内唯一可用的事实是 `cost_price` 与 `quantity`（不随行情变）。
- 因此「现价」列也**不能回退** `PositionItem.current_price` —— 它与上面两个字段同属成交时点写入，
  大概率就是买入时的价。拿它继续算，会得到一个看着像实时、其实是建仓当刻的数字。
  取不到实时价时，两列一起显示 `--`。
- 注意此处收益率**不含手续费**（后端快照口径可能含），差异属于已知取舍。

**创建策略对话框**

顶部为「策略」/「参数」两个标签页。对话框宽度 760px，**高度固定**为 `min(视口高度 − 40px, 860px)`（创建、编辑两个对话框高度一致）。

*「策略」标签页*

**① 策略选择 —— 卡片式，可左右滑动**

### 5.3 策略监控 `/strategy-monitor`

实时查看交易信号流。

**标题栏**：左侧「策略监控」，右侧绿色胶囊标签 +「**实时更新中**」。

**信号统计卡片（4 个，数据均取自内存，不产生后端请求）**

| 卡片 | 含义 |
| --- | --- |
| 全部信号 | 当前保留窗口内（12 小时）的信号总数 |
| 买入信号 | 其中方向为「买入」的条数 |
| 卖出信号 | 其中方向为「卖出」的条数 |
| 今日信号 | 今日 0 点起的信号条数 |

**策略卡片（横向排列，可左右滚动）**

每张卡片对应一个用户策略，结构对齐原型 `doc/prototypes/strategy-monitor.html`。

| 区域 | 内容 |
| --- | --- |
| 左上图标 | 按策略类型取图标，配色按卡片序号循环（蓝 / 紫 / 橙 / 绿） |
| 标题 | 策略名称（自定义名称优先，无则回退策略模板名） |
| 副标题 | 运行中显示「已运行: X天 Y小时 Z分」；已停止 / 已暂停则显示状态文案 |
| 右上按钮 | **启动** / **暂停** / **停止** 三个按钮，按当前状态决定各自可用性 |
| 三列指标 | 信号触发（次） / 当前持仓（只） / 浮动盈亏（元） |
| 底部 | 左侧「最新信号: 买入 600519 (11:20:15)」，右侧「详情回测 >」 |

**三个按钮的可用性（状态机）**

| 策略状态 | 启动 | 暂停 | 停止 |
| --- | --- | --- | --- |
| `running` 运行中 | 置灰 | 可用 | 可用 |
| `paused` 已暂停 | 可用（恢复运行） | 置灰 | 可用 |
| `stopped` 已停止 | 可用 | 置灰 | 置灰 |

点击后立即写回后端策略状态，并就地刷新卡片（不必等待下一轮轮询）；成功 / 失败均有提示。

**指标口径**

| 指标 | 口径 |
| --- | --- |
| 信号触发 | 内存中该策略的信号条数，即**近 12 小时**触发次数（受信号保留窗口限制） |
| 当前持仓 | 该策略最新一条执行记录里的持仓只数 |
| 浮动盈亏 | **已实现 + 未实现** 两段之和；涨红跌绿，带正负号与千分位，如 `+¥4,520` / `-¥840`；任一段算不出时显示 `--` |
| 已运行 | `当前时间 − user_strategy.update_time`；后端在每次策略状态变更时刷新该字段，字段缺失时显示 `已运行: --` |

浮动盈亏的两段构成：

| 段 | 口径 | 数据来源 |
| --- | --- | --- |
| 已实现 | 该策略历次**卖出**累计的收益 | 最新一条执行记录的 `current_profit`（与 `user_strategy.total_profit` 同义，见下） |
| 未实现 | `Σ(实时价 − 成本价) × 持仓数量`，**现算** | 执行记录的 `positions` + 一次批量实时行情 |

- 已实现段取**执行记录**的 `current_profit`，而不是 `user_strategy.total_profit`。二者是同一个数
  （后端卖出时把 `current_profit` 同步到 `total_profit`），但会话缓存只在**页面进入时**刷新一次
  （60s 节流），而本页是常驻轮询页，停留在本页期间缓存会一直冻结在进页那一刻。
  执行记录跟随 30s 快照一起刷新，且与持仓同源。历史记录缺该字段时回退到 `total_profit`（走容错解析）。
- 未实现段**不使用**持仓里的 `profit_rate` / `profit_amount`：这两个是**成交时点值**
  （买入时写入、持仓期间后端不参与计算、直到卖出那一刻才重算）。持仓期内唯一可用的事实是
  `cost_price` 与 `quantity`。
- **任一持仓缺实时价 ⇒ 整张卡片显示 `--`**：既不用剩余持仓凑一个会被读成全仓浮盈的数字，
  也不单独显示已实现段（那同样是残缺值）。缺实时价不影响「当前持仓」只数，那个仍按执行记录计。
- **从未成交**（没有任何执行记录）时显示 `--`；**已清仓**（有执行记录但持仓为空）时未实现段为 0，
  浮动盈亏就是已实现段。
- 实时行情与执行记录共用同一个 30s 节流窗口（1 秒轮询不会放大行情请求）。

- 卡片上的「最新信号」只显示**该策略自身**最近的一条，不同策略之间互不混淆。
- 「详情回测 >」跳转到**策略回测记录页** `/strategy-backtest?strategy_id=<策略模板ID>&source=monitor`（详见 5.9 节）；该页左上角的「返回策略监控」会回到本页。
- 无策略时显示「暂无策略，请先在策略列表创建」。

**实时信号日志**

- 右上角筛选标签：**全部 / 买入 / 卖出**（选中态高亮；切换后使用已拉取的数据立即重渲染，无需等待下一轮刷新）。
- 表格列（7 列）：

| 列 | 说明 |
| --- | --- |
| 时间 | 精确到秒 |
| 策略 | **用户策略名称**（`user_strategy.name`），同模板多实例各自显示自己的名字 |
| 股票代码 | 代码在上、**股票名称在下**；名称查不到时显示 `--` |
| 信号类型 | 买入（红）/ 卖出（绿） |
| 成交价格 | 无数据显示 `--` |
| 盈亏率 | 带正负号，涨红跌绿，保留 2 位小数 |
| 原因 | 触发原因文本，过长省略 |

- 2026-09-23 调整：去掉「盈亏额」列（金额按成交时点算，与卡片上的浮动盈亏口径不同，并排展示容易误读）；
  股票名称走进程级缓存（名称是静态数据），只在首次出现某个代码时请求一次。

- 排序：**按时间倒序**（最新的在最上面）。
- 每个策略最多保留最近 200 条，整体仅保留 **12 小时内**的信号（超期自动清理）。
- 无数据显示「暂无交易信号」。

**自动刷新**：信号日志每 1 秒刷新一次；策略卡片数据无变化时不重建（避免按钮 hover 态闪烁），持仓数据每 30 秒拉取一次。

- 主题是**即时生效**型设置：拨动开关会立刻写入用户偏好（`theme_mode`），不需要再点「保存更改」；翻页、重新登录后保持所选主题。
- 主题归属是**会话级**的：A 用户切浅色不会影响 B 用户。
- 首次进入时按用户偏好恢复；从未保存过偏好的用户保持默认深色。
- 登录页（`/login`）**固定深色**（严格对齐 `doc/prototypes/login.html` 原型），不跟随主题。
- 图表（ECharts）用 canvas 绘制，无法解析 CSS 变量，因此**已打开的图表要等下次进入页面才会换成新主题的配色**（配色本身已按主题取值）。

### 5.9 策略回测记录 `/strategy-backtest`

查看某个策略的历史回测结果与逐笔成交明细（**只读页**，不发起新的回测）。

**入口（两处）**

| 入口 | 位置 |
| --- | --- |
| 详情回测 > | 策略监控页策略卡片右下角 |
| 回测记录（图标按钮） | 策略列表页表格「操作」列，编辑按钮左侧 |

**返回：从哪进就回哪**。返回按钮的文案与目标都跟随入口，侧边栏高亮同样跟随入口：

| 入口 | 返回按钮 | 返回目标 | 侧边栏高亮 |
| --- | --- | --- | --- |
| 策略监控页 | 「← 返回策略监控」 | `/strategy-monitor` | 策略监控 |
| 策略列表页 | 「← 返回策略列表」 | `/strategies` | 策略列表 |

> 入口信息通过查询参数 `source` 传递（取值 `monitor` / `strategies`，见「附：页面路径速查」）。参数缺失或非法时回退为策略监控；未指定策略的空态下，返回按钮同样跟随入口。

**页面结构**

| 区域 | 内容 |
| --- | --- |
| 标题栏 | 返回按钮 + 「策略回测记录」+ 副标题（策略名 ｜ 共 N 条回测记录）+ 刷新按钮 |
| 左栏「回测历史」 | 该策略的全部回测记录，按 `create_time` **倒序**；每条显示创建时间、收益率、回测区间与交易笔数 |
| 右栏详情 | 关键指标卡（6 个）+「回测汇总」+「交易明细」 |

- 进入页面时**默认选中最新一条**记录；点击左栏任意一条即可切换，选中项左侧有强调边与主色底。
- 指标卡：回测收益率 / 回测收益额 / 基准收益率 / 最大回撤 / 年化收益率 / 夏普比率。
- 回测汇总：总交易次数 / 盈利次数 / 亏损次数 / 胜率 / 平均单笔盈亏 / 最大单笔盈利 / 最大单笔亏损 / 年化收益率 / 基准年化 / 夏普比率 / 最大回撤 / Alpha / 初始资金 / 期末资金 / 交易日数 / 基准代码。
- 交易明细：序号 / 股票代码 / 买入日期 / 卖出日期 / 买入价 / 卖出价 / 盈亏率（涨红跌绿）。

**指标口径**

| 指标 | 口径 |
| --- | --- |
| 回测收益率 | `result_data.backtest_return_rate`，后端存的是**比例**（0.0543 = 5.43%），页面乘 100 展示 |
| 回测收益额 | `result_data.backtest_profit`，带正负号与千分位（`+¥5,430` / `-¥840`） |
| 基准收益率 | `result_data.benchmark_return_rate`（同为比例） |
| 最大回撤 | `result_data.max_drawdown`（比例），风险指标，大于 0 时用绿色 |
| 年化 / 夏普 / 胜率等 | 取 `result_data.summary`，后端给的**已经是百分数**，不再乘 100 |
| 缺失字段 | 汇总区显示 `-`，不显示 0（避免把「后端没给」误读成「结果是 0」） |

**刷新**：不做自动轮询（回测只在跑完一次回测时新增），进入页面时拉取一次，之后点「刷新」手动更新。

**空态与异常**

| 情况 | 页面表现 |
| --- | --- |
| 该策略没有回测记录 | 左栏「暂无回测记录」，右栏「该策略还没有回测记录」 |
| 最新一条没有产生成交 | 明细区显示「本次回测没有产生任何委托成交」 |
| 未带 `strategy_id` 进入（如登录回跳丢了查询串） | 提示「未指定要查看的策略」，并给出返回入口（该入口同样跟随 `source`），**不会去请求后端** |
| 拉取失败 | 显示「回测记录加载失败」+ 原因 + 「重试」按钮（不会退化成空白页） |

> **一个策略可能有多条记录**：只选中某一条时，页面展示的就是那一条的指标与明细；记录条数显示在标题副标题与左栏标题处。

> **同一模板的多个策略会看到同一份回测记录**：回测按**策略模板 ID**（`/api/strategy/{strategy_id}/backtest`）关联，而卡片/行代表的是用户策略——同一模板被复用时，它们的「详情回测」内容相同。这是接口与数据模型决定的，不是页面串数据。

## 8. 已知边界（当前版本）

以下能力在代码中已具备接口或已实现，但**当前界面未提供入口**，使用前请知悉：

1. **策略的启停**：**策略监控页**的卡片上提供「启动 / 暂停 / 停止」；**策略列表页**可通过**编辑对话框的「运行状态」**切换状态，另有「创建 / 查看详情 / 回测记录 / 编辑」，没有独立启停按钮与删除按钮（删除能力已在后端封装，暂未接入界面）。
2. **策略回测的发起**：只有**查看**已有回测记录（`/strategy-backtest`）；页面上没有「开始回测」按钮，回测需由服务端 / 策略侧发起。
3. **注册页的「记住我」**：勾选框默认选中，但未与登录流程绑定。
4. **侧边栏品牌标识 QTrade**：仅作展示，点击不跳转。
5. **股票池「查看股票」**：以浮层消息列出前 20 个代码，若要逐只查看行情，请使用「股票行情」页。
6. **黑名单页的搜索框**：输入框已渲染但未绑定过滤逻辑，输入无效。
7. **深色模式的持久化**：主题未落盘，每次进入页面都会重置为深色（详见 5.7 节）。
8. **`pages/recommend_page.py`（推荐关注）**：代码存在但未注册任何路由，界面上无法访问。
9. **回测资金曲线**：后端只提供逐笔成交（`trades`），没有每日净值序列，因此回测页不画曲线（画出来只能是编的数据）。

```
/login                  登录 / 注册

/strategies             策略列表
/strategy-monitor       策略监控
/strategy-select        策略选股
```

> **页面参数一律走查询参数**（如 `/strategy-backtest?strategy_id=…`），不要用 `{id}` 动态路径：白名单是精确匹配，动态路径会被限流中间件当成未知路径计数。URL 用 `core/routes.py` 的构造函数生成（如 `backtest_route()`），不要在页面里手拼路径。

| `strategy_id` | 建议 | 策略模板 ID | 缺省时页面显示「未指定要查看的策略」空态，不请求后端 |
| `source` | 否 | `monitor` / `strategies` | 入口页面标识，决定「返回」按钮的文案、目标与侧边栏高亮；缺省或非法值回退 `monitor` |
