## 1. 技术选型

| 项 | 选择 | 理由 |
| --- | --- | --- |
| 框架 | **微信原生小程序**（非 uni-app / Taro / mpvue） | 项目只需微信一端；原生可省掉一层编译与运行时，自定义 TabBar、canvas 2d、WS 等能力都是第一手 API |
| 导航 | 全局 `navigationStyle: custom` + 自绘 `q-navbar` | 设计稿要求状态栏与导航栏一体化、可放右侧操作按钮 |
| 底部栏 | `tabBar.custom: true` + `custom-tab-bar` | 图标按设计稿用 CSS 绘制，不引入图片资源 |
| 图表 | **canvas 2d 自绘**（`components/q-chart`） | 设计交付说明第 9 节建议引入 ECharts，但小程序引 npm 需构建、体积大；蜡烛图/折线图逻辑不长，自绘可零依赖，也便于严格按「涨红跌绿」与主题令牌取色 |
| 主题 | WXSS CSS 自定义属性（`.root` / `.root.theme-dark`） | 与 `ui/tokens.css` 一一对应，换肤只需切根节点 class |
| 实时信号 | WebSocket 优先 + HTTP 轮询兜底（`utils/ws.js`） | 小程序无法直连 MQTT（`wx.connectSocket` 只支持 WS/WSS），需后端提供 MQTT→WS 网关 |
| 第三方依赖 | **无** | `npm` 依赖为 0，无构建步骤，克隆下来用开发者工具直接打开即可运行 |

## 3. 全局机制

### 3.1 请求链路（`utils/request.js`）

所有后端调用都走同一个 `request(opt)`：

1. 自动拼接 `config.BASE_URL`；
2. 自动附加 `Authorization: Bearer <token>`（`auth:false` 的登录/注册接口除外）；
3. 统一解包后端 `ApiResponse { code, message, data }`：
   - `code === 0` → `resolve(data)`；
   - `code !== 0` → `reject(BizError)`；
4. **401 统一处理**：清会话 + 跳登录页，并用 1.5s 防抖避免并发请求重复 `reLaunch`；
   （登录/注册这类匿名请求的 401 不走此分支，直接由调用方提示「账号或密码错误」）
5. 409 / 422 / 400 / 500 的 `detail` 尽量透出，便于定位；
6. `silent: true` 时不弹错误 toast —— 所有轮询与「补充数据」类请求（finance/pool stocks 等）都用它，避免弱网下刷屏。

`req()` 是 `request()` 的便捷包装：自动 toast 错误后继续抛出，页面可继续 `catch` 做局部降级。

### 3.2 会话与缓存（`utils/store.js`）

| 数据 | 存放位置 | 有效期 | 说明 |
| --- | --- | --- | --- |
| token / 账号 / 角色 / 手机号 | Storage（`qt_session_v1`） | 直至登出或 401 | 冷启动即可恢复，无需重新登录 |
| 主题模式 | Storage（`qt_theme_mode`） | 永久 | 与后端 `theme_mode` 双向同步 |
| 用户策略列表 | 内存 | 60s | 对齐 Web `UserStrategyManager.RELOAD_MIN_INTERVAL_SECONDS` |
| 策略模板 map | 内存 | 60s | 全局公共数据，多用户共享安全 |
| 股票池列表 | 内存 | 60s | — |
| 交易信号窗口 | 内存 | 12h 滚动 | 对齐 Web `SignalManager.SIGNAL_RETENTION_HOURS`，按 id 去重，最新在前 |

派生统计直接读缓存，**不产生额外请求**：
- `countStrategies()` 策略总数
- `countRunning()` 运行中数量（严格 `status === 'running'`）
- `countMonthNew()` 本月新增（`create_time` 字符串前 7 位 == 本地 `%Y-%m`）

### 3.3 主题系统（`utils/theme.js`）

三条例外规则（都来自 Web 端实证）：

1. **取值是小写** `"light"` / `"dark"`，不是 `"dark"` / `"light"` 之外的任何写法；
2. **判断「用户是否真的选过主题」不能只看 `theme_mode`**。后端在用户从未保存过偏好时返回的是模型默认值 `light`，那不是用户的选择。正确判据是 **`id` 与 `update_time` 同时为空**（`resolveFromPrefs()`）；
3. **主题是即时生效型**：拨动开关立刻写 `theme_mode` 并落库，不需要点「保存更改」；其余偏好项才走保存按钮。

接入方式：页面 `onShow` 里调 `theme.applyTo(this)`，页面 data 即获得 `themeClass` / `statusBarHeight` / `navbarHeight` / `safeBottom`，根节点写 `<view class="root {{themeClass}}">` 即可自动换肤。

> `custom-tab-bar` 不在 `.root` 子树内，拿不到 CSS 变量，因此它的配色是内联写死的（见 `custom-tab-bar/index.wxss` 注释）。

### 3.4 数值格式化与两个缩放陷阱（`utils/format.js`）

这是本项目**最容易出显示 bug** 的地方，因此把两类百分数拆成两个函数名，调用点必须显式选择：

| 函数 | 语义 | 典型字段 |
| --- | --- | --- |
| `fmtPctRatio(v)` | 入参是**小数比率**，内部 ×100 后输出 `+2.31%` | `change_percent`、`change_pct`、`turnover`、`amp` |
| `fmtPctRaw(v)` | 入参**已经是百分数**，直接输出 `+12.50%` | `net_profit_growth_rate`、`profit_rate` |

其它约定：
- 价格：`fmt.price()` 保留 2 位小数**不加千分位**（`1682.50`）；表格场景用 `fmt.priceGroup()` 带千分位；
- 颜色判向：`toneOf(v)` → `'up'|'down'|'flat'`，A 股约定 **涨红跌绿**；
- 策略「总收益」= `total_profit / initial_amount × 100`（与 Web 同公式），结果已是百分数，直出。

### 3.5 信号通道（`utils/ws.js`）

```
页面订阅 ws.start({pollInterval, onSignals, onStatus})
        │
        ├─ config.WS_URL 非空 → wx.connectSocket(url?token=xxx)
        │      成功 → mode='ws'，25s 心跳 ping，停止轮询
        │      失败（连续 2 次）→ mode='poll'，按最小 pollInterval 轮询
        │                          /api/trade_signal/list，同时指数退避重连
        └─ config.WS_URL 为空 → 直接轮询
```

- 轮询间隔取**所有订阅者里的最小值**：监控页 3s、仪表盘 10s，谁在前台谁是主导；
- 最后一个订阅者取消时自动 `shutdown()`，不留后台定时器；
- 页面 `onHide` / `onUnload` 必须调用返回的 `stop()`，避免离开页面后仍在轮询。

### 3.6 响应式与安全区

- 设计稿基准宽 375pt → 小程序 750rpx = 屏宽，**令牌里的 px 一律 ×2 转 rpx**，颜色值原样保留；
- 顶部不使用 CSS `env(safe-area-inset-top)`：Android 微信返回 0、iOS 返回刘海高度，直接用会导致两端导航栏不等高。统一取 `wx.getWindowInfo().statusBarHeight` 作为状态栏高度传给 `q-navbar`（见 `utils/system.js` 注释）。

### 4.1 `pages/login` 登录 / 注册 / 微信一键登录

- **三态**：登录表单 / 注册表单 / 微信绑定表单（`bindTicket` 非空时进入）；
- **协议勾选**：未勾选时登录、注册、微信登录均被拦截（设计稿要求，Web 无此门禁）；
- **校验规则刻意与 Web 保持一致**：只做长度与非空判断，**不加正则**。
  Web 提示文案写着「4-16 位字母或数字」，但源码里没有正则，这里不擅自加严；
- 逐字段校验，**首次失焦触发**，输入即清除该字段错误；
- 注册成功后**自动登录**（对齐 Web）；自动登录失败则切回登录表单并提示「请手动登录」；
- 「忘记密码」仅提示「请联系管理员重置密码」，无接口调用（与 Web 一致）；
- **微信一键登录**：`wx.login` 拿 code → `POST /api/user/wx_login`。
  后端返回 `need_bind` / `bind_ticket` 时切换到绑定表单，走 `POST /api/user/wx_bind`；
  接口若返回 404/405，提示「微信登录接口尚未就绪，请使用账号密码登录」——**后端未就绪时功能可降级，不阻塞上线**；
- 登录成功后优先回跳来源页（`auth.takeRedirect()`），无来源则进首页。

### 4.2 `pages/home` 仪表盘

4 张统计卡 + 累计收益图 + 近期运行状态 + 近期更新策略表 + 通知铃铛。

| 区块 | 数据来源 | 刷新 |
| --- | --- | --- |
| 统计卡（策略总数 / 运行中 / 股票池数量 / 今日信号数） | `store` 缓存 + 信号窗口 | 进页面 + 信号通道推送 |
| 累计收益概览图 | `GET /api/user_strategy/executions` | 60s |
| 近期运行状态（最多 4 条） | 信号窗口，**只取运行中策略**的信号 | 信号通道推送 |
| 近期更新策略（最多 5 行） | 用户策略 + 策略模板 + 执行结果收益率 | 60s |
| 通知角标 / 消息面板 | `GET /api/system_message/user_messages` + `POST /api/system_message/read` | 10s |

- 收益图支持 7 天 / 30 天 / 1 年切换，按 `current_return_rate × 100` 取点、同一日期取最后一次；
- 图表用 `q-chart kind="profit"`，切换周期只重算数据不重建组件；
- 信号推送到达时**只更新「今日信号数」这一张卡**，不做整块 setData；
- 统计卡可点击跳转：股票池卡 → 行情 Tab，策略类卡 → 策略 Tab；策略表行 → 策略详情；
- 通知：角标数是服务端 `is_read` 为假的条数（不再用本地 `_seenMsgIds` 判重）。点铃铛开
  `.msg-panel` 面板，按未读 / 历史分区摊平成 `msgRows`（`type: 'section' | 'item'`），
  **只有未读项可点**，`onMsgTap` 调 `markRead` 后把本地 `is_read` 置真并重算角标。

### 4.3 `pages/quotes` 股票池列表

对齐 Web `/stock-pools`：

- 统计栏：总数 / 自动更新 / 静态池；
- 搜索：按**名称与描述**做前端过滤（与 Web 一致）；
- 卡片：类型徽标 + 名称 + 描述 + 「N 只股票」+ 更新频率文案 + 「查看股票」/「编辑」；
- 末尾虚线占位卡「创建新股票池」；
- 点卡片 → 池内行情；点编辑 → 编辑股票池。

⚠️ **已知边界（与 Web 同源）**：
1. 后端 `PoolInfo` **没有 `type` 字段**，创建接口也不接受 `type`，因此池类型真机上恒为「手动维护」，统计栏的「自动更新」恒为 0。页面逻辑已按完整枚举写好，后端补字段后无需改代码；
2. 后端 `/api/pool/{name}/stocks` 只返回 `code` + `add_time`，**没有数量字段**，股票数量必须逐池调一次 `/stocks` 取长度 —— 即 N+1 请求。池多时首屏偏慢，故这些请求全部 `silent`。

### 4.4 `pages/pool-quotes` 池内行情

- `api.fetchPoolQuotes(name)` 组合调用：`/stocks` → `/real_time` → 并发补 `/finance/valuation` + `/finance/profit`；
- 补齐规则与 Web 一致：**仅当行情里没有 `ttm_pe` / `net_profit_growth_rate` 时才用财务接口的值覆盖**；
- 排序以**池内代码顺序**为准（行情缺失的置后），与 Web 同；
- 15s 自动刷新（`config.POLL.quotes`），带「更新于 HH:MM:SS」提示；
- 点行进个股详情；支持池内搜索。

### 4.5 `pages/pool-form` 创建 / 编辑股票池

**创建流程**：基本信息 → 所属行业（多选）→ 自动筛选条件（市值亿 / PE）→ 手动追加股票 → 实时预览 → 保存。

**预览逻辑（与 Web 完全同源）**：

| 条件组合 | 候选来源 |
| --- | --- |
| 仅行业 | 逐行业调 `/api/stock_info/industry` 后取**并集** |
| 仅筛选条件 | `/api/screener/search` |
| 两者都有 | screener 结果 **∩** 行业集合 |

- **手动追加的股票无视筛选条件强行入池**（Web 既有语义），预览列表里用「已追加」标签标出；
- 「刷新预览」按当前条件重算；「追加选中股票」把勾选项写入「手动追加股票」文本框；
- 保存链路：`POST /api/pool/create` →（有股票时）`POST /api/pool/{name}/stocks/add` → 清缓存 → 返回。

**编辑流程**：
- 名称与描述**只读**（服务端限制，页面显式提示）；
- 「当前股票」表支持多选 + 「移除选中」。被剔除的股票先从界面摘出并记入 `pendingRemove`，点「保存修改」时才真正提交（`DELETE /stocks/remove`）—— 之所以要单独记账，是因为摘掉之后勾选态就不存在了，不能再反推；
- 危险区「删除股票池」→ 二次确认 → `DELETE /api/pool/{name}`。

**校验根因**（Web 的提示文案原样保留）：`股票池名称不能为空` / `请至少手动追加一只股票或设置筛选条件` / `请先在预览表格中勾选股票` / `选中的股票已存在`。

> 注意：后端创建接口**只接受 `name` / `description`**，行业与筛选条件不会随创建提交。它们的作用是「把符合条件的股票算出来」，最终入池的是**股票代码**。

### 4.6 `pages/search` 搜索与条件筛选

两个标签页：

1. **按代码 / 名称**（`api.searchStockQuotes`）：
   先 `GET /api/stock_info/list`（`limit` 必须显式给大值，默认只返 100）在 `code` / `name` / `pinyin` 上做前端匹配，取前 30 个代码，再取实时行情并补估值与利润。
2. **按财务条件**（`GET /api/screener/search`）：市值（亿元）、PE(TTM)、利润率。
   ⚠️ **利润率入参是小数比率**：页面按 % 输入（15 表示 15%），提交前 ÷100，返回后 ×100 展示。

两个标签页的结果都点得进个股详情。

### 4.7 `pages/stock-detail` 个股详情

三段内容严格对齐 Web 的「个股分析」弹窗：

| 段 | 内容 | 取数 |
| --- | --- | --- |
| ① 实时行情 | 大字最新价 / 涨跌幅 / 涨跌额 + 今开 / 最高 / 最低 / 昨收 / 成交量 / 成交额 | `GET /api/market/real_time?code=`，**取返回列表的最后一条**（Web 同源） |
| ② 价格走势（近 15 天） | 日K 蜡烛图 ⇄ 分时折线，分时可选具体交易日 | 日K：`/api/market/kline/day`，`start=今天-15天`；分时：`/api/market/kline/minute`，`start="日期 09:30:00"`, `end="日期 15:00:00"` |
| ③ 买卖信号（近 15 天） | 时间 / 成交价 / 收益 / 原因 | `GET /api/trade_signal/list?stock_codes=xxx&start_time=... 00:00:00` |

细节：
- ⚠️ **分时接口的参数名是 `start` / `end`，不是 `start_time` / `end_time`**（与 `real_time` 不同），这是最容易调错的一处；
- 分时可选日期 = 日K 数据里出现过的交易日（降序取最后一天为默认），与 Web 一致；
- 图表上用圆圈标注买卖信号（买红 / 卖绿）：日K 按日期对齐，分时按 `HH:MM` 就近吸附；
- 日K 只画最近 90 根，保证手机上蜡烛宽度可辨识；
- **收益只在卖出方向展示**（Web 同源规则），格式 `收益 +12.34%`，`profit_rate` 已是百分数不再 ×100。

### 4.8 `pages/strategies` 策略列表（Tab3）

- 顶部统计：策略总数 / 运行中 / 本月新增；
- 筛选：搜索（名称+描述）、类型下拉、状态下拉、重置。**任一条件变化都回到第 1 页**；类型选项由当前数据动态汇总；
- 每页 10 条，页脚「显示第 X-Y 条结果，共 N 条」+ 上一页 / 页码 / 下一页，首末页置灰，支持上拉加载；
- 卡片信息（把 Web 的 6 列表格改为纵向卡片，手机宽度放不下 6 列）：
  名称 + 状态徽标 / 描述 / 类型 + 持仓上限 + **总收益** / **最近信号**；
- 「总收益」= `total_profit / initial_amount × 100`，涨红跌绿；
- 「最近信号」取信号窗口内该策略的**最新一条**，文案 `买入 600519`，买红卖绿；
- 点卡片展开**内嵌详情面板**，三个标签：
  - **持仓信息**：代码 / 名称 / 数量 / 成本 / 现价 / 盈亏（缺 `profit_amount` 时按 `(现价-成本)×数量` 补算，与 Web 一致）；
  - **订单明细**：以持仓股票代码为参数取最新订单（`/api/order/latest`），日期 / 股票 / 方向 / 数量 / 价格 / 成交额；
  - **运行日志**：`GET /api/user_strategy/{id}/runlog`，逐行「时间 [级别] 内容」。
  三个标签的数据在展开时**一次性拉齐**，切换标签不再请求（对齐 Web「不重新加载整页」）；
- 行尾「详情」→ 完整详情页，「编辑」→ 编辑策略。

### 4.9 `pages/strategy-detail` 策略详情

列表页内嵌面板的完整版，面向从监控页 / 仪表盘跳进来的场景：

- 概览卡：名称 / 状态 / 类型 / 描述 / 总收益 / 累计盈亏（元）/ 初始资金 / 关联股票池（可点进池内行情）/ 创建时间；
- **策略参数**：以模板 `default_params` 决定「有哪些参数 + 中文名」，用户已保存值优先；
- 持仓 / 订单 / 日志三个标签，口径与列表页完全一致。

### 4.10 `pages/strategy-form` 创建 / 编辑策略

**参数结构是这里最大的坑**：

```
模板 default_params = { match: { min_price: { desc: '股价下限', value: 3.0 }, ... }, buy: {...}, sell: {...} }  ← 三层
提交 strategy_params = { match: { min_price: 5.0 }, ... }                                                    ← 两层
```

- 展示/编辑以 `default_params` 为准（拿到中文 `desc` 与默认值），用户已保存值覆盖默认值；
- 数字型参数渲染为数字键盘输入框，提交时 `parseFloat` 还原为 `number`；非数字型原样提交字符串；
- 用户保存了模板里不存在的分组时**补一栏**，避免参数「查不到」；
- 保存校验与提示文案原样对齐 Web：`请点击卡片左上角勾选策略模板` / `请输入策略自定义名称` / `请选择股票池` / `请输入初始模拟资金`；
- 创建提交 `POST /api/user_strategy/create`，`status` 固定为 `stopped`（与 Web 一致，状态由服务端驱动）；
- **409 的两种含义分别提示**：
  - 创建时 409 → 「该策略已关联，请在列表中编辑，请勿重复创建」；
  - 编辑时 409 → 「已存在同名策略，请更换名称」（后端 `error == "duplicate_name"`）；
- **编辑模式模板只读**，页面显式提示「编辑时不可更换策略模板」，传参只含 `name / pool_id / initial_amount / max_stock_count / strategy_params`；
- 模板详情 `default_params` 列表接口不返回，因此选中模板后**单独调一次** `GET /api/strategy/id/{id}`。

### 4.11 `pages/strategy-select` 策略选股

- 顶部「今日选股 · YYYY-MM-DD」+ 刷新按钮；策略标签栏切换；
- ⚠️ **`start_time` / `end_time` 必须传 `YYYY-MM-DD`**，传带时分秒会查不到数据；
- 数据源 `/api/strategy_select_stocks/list` 直接返回带实时行情的 `StrategySelectStockWithRtItem`（含 `name` / `price` / `change_percent` / `change_amount` / `turnover` / `score`），**只有 `ttm_pe` 与 `net_profit_growth_rate` 需要用 `/api/finance/*` 补两次**；
- **后端已按 `score` 正向排序并对同 code 去重，前端不再重排** —— 重排会让展示的 `price` / `rt_update_time` 在刷新之间抖动；
- 切换标签**强制重新拉取**（不读缓存），保证行情最新；
- 主表 4 列（代码/名称、评分、最新价、涨跌幅）+ 每行下方次级指标（涨跌额、换手、PE、利润增长），比 Web 的 8 列表格更适合窄屏；
- 缩放：`change_percent` / `turnover` ×100；`net_profit_growth_rate` 不乘；`score` 保留 2 位小数。

### 4.12 `pages/monitor` 策略监控

- 实时状态胶囊：「实时更新中」（WS 已连）/「轮询更新中」（降级）；
- 4 张统计卡：**全部 / 买入 / 卖出 / 今日**，全部取自本地信号窗口，**不产生任何后端请求**；
- 筛选标签：全部 / 买入 / 卖出，切换后用已拉取的数据立即重渲染；
- 信号卡：时间（秒）/ 策略（可点进详情）/ 股票代码（可点进行情）/ 信号类型（买红卖绿）/ 成交价格 / 盈亏率 / 盈亏额 / 原因；
- 按时间**倒序**；仅保留 `SIGNAL_RETENTION_HOURS`（12 小时）内的信号，最多 200 条；
- 刷新：Web 是「后端订阅 MQTT → 内存 → 前端每秒读内存」，小程序读的是 `utils/ws.js` 维护的**同一份滚动窗口**，刷新周期取 `config.POLL.monitor`（默认 3s，弱网下比 1s 更省电）；
- 缩放：`profit_rate` 已是百分数（`fmtPctRaw`），`profit_amount` 保留 2 位小数带符号。

### 4.13 `pages/preferences` 个人喜好设置

三张卡片：界面显示 / 企业微信推送 / 手机短信推送。

- ⚠️ **`PUT /api/user/preference` 是全量替换语义**，因此每次提交都要把没改的字段一起带上，否则会被清空。`payload()` 以服务端返回值为底，再用当前界面值覆盖；
- **深色模式即时生效 + 立即落库**，不需要点「保存更改」；其余项走保存按钮；
- 关闭「启用推送」时 Webhook 输入框隐藏，关闭「启用短信推送」时手机号隐藏（与 Web 一致）；
- 本页在 Web 基础上**补了一条前端校验**：开启推送却未填地址 / 手机号时不允许保存，避免把空值写进后端导致策略触发时静默失败（属于改进，见第 7 节差异清单）。

### 4.14 `pages/blacklist` 黑名单股票管理

- 蓝色提示横幅：黑名单逻辑生效于所有策略；
- 列表卡：代码 / 名称 / 拉黑时间 / 拉黑原因 / 用户 / 「移除名单」；
- **「用户」列的回退链**：`user_name` → `username` → `user_id` → 当前登录账号（后端 `BlacklistInfo` 实际只返回 `code` / `add_time` / `reason`，所以真机上显示的是当前账号）；
- 添加：底部弹层，多行输入，**中英文逗号、顿号、分号、空白、换行统一当分隔符**；原因可选；
- 校验：`请输入股票代码` / `未识别到有效的股票代码`；
- 移除：二次确认后即时生效（`POST /api/blacklist/remove`）。

### 4.15 `pages/profile` 我的（Tab4）

Web 端没有独立「我的」页（侧边栏直接铺开所有入口），小程序把它聚合为一页：

- 账号卡片：首字母头像 / 账号 / 角色标签 / 打码手机号；
- 数据概览：策略总数 / 运行中 / 本月新增（直接读 `store` 缓存统计）；
- **深色模式快速开关**（与「个人喜好」页同一实现：即时生效 + 落库）；
- 功能入口：策略监控 / 策略选股 / 股票池与行情 / 搜索与筛选 / 个人喜好 / 黑名单 / 关于；
- 危险区：退出登录、注销账号（注销需二次确认 + 输入密码，走 `DELETE /api/user/account`）。

## 7. 与 Web 端的有意差异

以下差异都是**为了适配手机交互或修正 Web 端的显示缺陷**，功能语义不变：

## 8. 离线静态自检（`tools/check.js`）

微信开发者工具之外，可用 Node 直接跑一遍结构自检，**不需要安装任何依赖**：

```bash
node tools/check.js
```

检查项：

1. **组件注册**：WXML 里用到的所有 `<q-xxx>` 是否已在 `app.json` 或页面 json 的 `usingComponents` 里注册；
2. **事件绑定**：WXML 里 `bind*` / `catch*` 绑定的处理函数是否在对应页面 JS 里存在；
3. **require 路径**：所有 `require('./xxx')` 的相对路径是否真实存在；
4. **页面清单**：`app.json` 的 `pages` 与实际文件是否一一对应（`.js` / `.wxml` / `.json` 三件套齐全）。

退出码非 0 表示发现问题，可直接接入 CI。

> 这个脚本解决的是**小程序最容易出的低级错误**：改了组件名忘了注册、删了方法忘了改绑定、挪了文件忘了改 require —— 这三类错误在开发者工具里往往只报一句模糊的编译失败，定位成本很高。

## 9. 已知边界与后端缺口

### 9.1 依赖后端补充的能力

| # | 缺口 | 影响 | 当前降级行为 |
| --- | --- | --- | --- |
| 1 | `PoolInfo` 缺 `type` 字段，创建接口不接受 `type` | 池类型恒为「手动维护」，「自动更新」统计恒为 0 | 逻辑按完整枚举写好，补字段即生效 |
| 2 | `POST /api/user/wx_login` 未实现 | 微信一键登录不可用 | 捕获 404/405 → 提示改用账号密码登录 |
| 3 | `POST /api/user/wx_bind` 未实现 | 微信绑定不可用 | 同上 |
| 4 | `/ws/trade_signal` WS 网关未实现 | 信号只能轮询 | `utils/ws.js` 自动降级为 HTTP 轮询 |
| 5 | `/api/pool/{name}/stocks` 不返回数量 | 股票池列表需 N+1 请求 | 并发拉取 + `silent`，可接受 |

新增接口的完整契约见 `doc/接口契约.md`。

### 9.2 其它边界

- 后端真实域名是 `http://example.com:8000`，**微信小程序真机与体验版只允许 HTTPS**，且域名必须在小程序后台白名单里。当前配置只能配合开发者工具勾选「不校验合法域名」联调，详见 `doc/上线步骤.md`；
- 小程序无法直连 MQTT，实时性依赖后端 WS 网关；
- `q-chart` 自绘图表不提供手势缩放 / 十字光标（Web 的 ECharts 有），当前以「最近 90 根 K 线 + 信号标注」满足查看需求。
