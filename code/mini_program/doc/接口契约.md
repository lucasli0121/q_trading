# QTrade 量化小程序 · 后端接口契约

> 本文档是小程序端与 `q_trading_server`（FastAPI）之间的**接口事实清单**。
> 所有条目都从后端路由源码与 `q_trading_cli` 调用层逐条核对得出，不含推测。
>
> 分两部分：
> - **第 1–4 节**：小程序**已在使用**的现有接口（后端无需改动）；
> - **第 5 节**：小程序**需要后端新增**的接口（当前有降级行为，不阻塞上线）。

---

## 1. 通用约定

### 1.1 地址与鉴权

| 项 | 值 |
| --- | --- |
| Base URL | `config.BASE_URL`（构建时注入，本机地址写在 `config/.env.local`，不入库） |
| 鉴权方式 | 请求头 `Authorization: Bearer <token>` |
| token 来源 | `POST /api/user/login` 返回的 `token` 字段 |
| token 存储 | 后端为 Redis 会话令牌；小程序侧存 Storage（`qt_session_v1`） |
| 匿名接口 | 登录、注册、策略模板列表等不需要 token |

### 1.2 统一响应包

所有接口都包一层 `ApiResponse`：

```json
{ "code": 0, "message": "success", "data": { } }
```

- `code === 0` 表示成功，业务数据在 `data`；
- `code !== 0` 表示业务失败，`message` 为原因；
- 小程序 `utils/request.js` 自动解包，页面只拿到 `data`。

### 1.3 HTTP 状态码语义（小程序侧的响应）

| 状态码 | 小程序行为 |
| --- | --- |
| 200 | 解包 `data`；若 `code !== 0` 抛 `BizError` |
| 401 | 清会话 + 跳登录页（1.5s 防抖）。**匿名请求（登录/注册）的 401 不走此分支**，直接提示「账号或密码错误」 |
| 403 | 提示「权限不足」（后端对不属于当前用户的用户策略返回 403） |
| 404 | 提示「接口不存在或数据已被删除」 |
| 409 | 按上下文分别处理：创建策略 → 「该策略已关联，请在列表中编辑，请勿重复创建」；编辑重名 → 「已存在同名策略，请更换名称」；添加黑名单重复 → 透出后端 `detail` |
| 422 | 提示「参数错误」，尽量透出 `detail[0].msg` |
| 0（无状态码） | 网络异常 / 超时（超时判定 `errMsg` 含 `timeout`） |

### 1.4 长列表的 `limit` 陷阱

后端多个列表接口默认 `limit=100`，**不显式传大值会被静默截断**。小程序统一用 `config.MAX_LIMIT = 5000`。涉及接口：

- `GET /api/stock_info/list`
- `GET /api/stock_info/industry`
- `GET /api/screener/search`
- `GET /api/trade_signal/list`

## 2. ⚠️ 字段缩放规则（最容易出错的一节）

后端有两类百分数字段，**缩放规则相反**，混用必然显示错误：

| 字段 | 后端返回 | 展示前处理 | 小程序函数 |
| --- | --- | --- | --- |
| `change_percent` / `change_pct` | 小数比率（`0.0076972` = 0.77%） | **×100** | `fmtPctRatio` |
| `change_amount` / `change_amt` | 绝对变动值（已是元） | 不乘 | — |
| `turnover` / `turnover_rate` | 小数比率 | **×100** | `fmtPctRatio` |
| `net_profit_growth_rate` | **已是百分数**（`12.5` = 12.5%） | **不乘** | `fmtPctRaw` |
| `profit_rate`（信号） | **已是百分数** | **不乘** | `fmtPctRaw` |
| `current_return_rate`（执行结果） | 小数比率 | **×100** | `fmtPctRatio` |
| `total_market_cap` | 亿元 | 不乘 | `fmtCapYi` |
| `profit_margin`（screener，**入参**） | 小数比率（`0.15` = 15%） | 前端按 % 输入后 **÷100** | — |

策略「总收益」由前端计算：`total_profit / initial_amount × 100`（与 Web 同公式）。

## 3. 用户与偏好

### 3.1 `POST /api/user/login` — 账号登录

| 项 | 内容 |
| --- | --- |
| 鉴权 | 匿名 |
| Body | `{ "account": "用户名/邮箱/手机号", "password": "..." }` |

**响应 `data`**（已核对 `web_api/routers/user.py`）：

```json
{
  "token": "xxxxx",
  "user_id": "xxx",
  "account": "xxx",
  "role": 0
}
```

> ⚠️ 登录响应**不包含** `email` / `phone`。小程序 `auth.persistLogin()` 里 `phone` / `email` 取不到时为空字符串，个人中心显示「未绑定」。
> 自定义导航栏与个人中心另需展示角色：`role === 0` 为管理员，否则普通用户。

### 3.2 `POST /api/user/register` — 注册

| 项 | 内容 |
| --- | --- |
| 鉴权 | 匿名 |
| Body | `{ "account": "...", "password": "...", "phone": "...", "email": "..." }` |

- `phone` / `email` 为空时小程序**不传该键**（而非传空字符串），避免后端校验异常；
- ⚠️ 后端注册校验**只有长度判断，没有正则**。小程序端刻意保持一致（用户名 4–16 位、密码 ≥8 位的提示文案来自 Web，但校验也只做长度），不擅自加严。

### 3.3 `POST /api/user/logout` — 退出登录

无 Body。调用方在成功后清空本地会话与全部缓存。

### 3.4 `DELETE /api/user/account` — 注销账号

| 项 | 内容 |
| --- | --- |
| Body | `{ "password": "..." }` |

### 3.5 `GET /api/user/preference` — 查询个人偏好

**响应 `data`**：

```json
{
  "id": "xxx",
  "theme_mode": "light",
  "enable_wx_push": false,
  "wx_push_url": "",
  "enable_phone_text": false,
  "phone": "",
  "update_time": "2026-09-16 12:00:00"
}
```

> ⚠️ **两条必须遵守的规则**：
> 1. `theme_mode` 取值为小写 `"light"` / `"dark"`；
> 2. 用户**从未保存过偏好**时，后端返回的是模型默认值 `light` —— **那不是用户的选择**。
>    正确判据：**`id` 与 `update_time` 同时为空**（小程序 `theme.resolveFromPrefs()`）。仅凭 `theme_mode` 判断会导致「没选过主题的用户被强制成浅色」。

### 3.6 `PUT /api/user/preference` — 保存个人偏好

| 项 | 内容 |
| --- | --- |
| Body | 全量提交下列 5 个字段 |

```json
{
  "theme_mode": "dark",
  "enable_wx_push": true,
  "wx_push_url": "https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=...",
  "enable_phone_text": false,
  "phone": ""
}
```

> ⚠️ **全量替换语义**：只传改动字段会把其余字段清空。小程序 `payload()` 以服务端返回值为底、再用当前界面值覆盖，保证 5 个字段始终齐全。
> ⚠️ 「深色模式」是**即时生效**型：拨动开关立刻提交一次 `PUT`（携带全部 5 个字段），不需要点「保存更改」。
> 字段白名单：`theme_mode` / `enable_wx_push` / `wx_push_url` / `enable_phone_text` / `phone`。

## 4. 业务接口

### 4.1 股票池 `pool`

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/api/pool/list` | GET | 股票池列表 |
| `/api/pool/create` | POST | Body `{ name, description? }` |
| `/api/pool/{name}` | DELETE | 删除池；`name` 需 URL 编码 |
| `/api/pool/{name}/stocks` | GET | 池内股票，**只返回 `code` + `add_time`** |
| `/api/pool/{name}/stocks/add` | POST | Body `{ codes: ["600519", ...] }` |
| `/api/pool/{name}/stocks/remove` | DELETE | Body `{ codes: [...] }` |

**`PoolInfo` 字段**：

```json
{ "id": "xxx", "name": "核心持仓池", "description": "...", "create_time": "...", "add_time": "..." }
```

> ⚠️ **`PoolInfo` 没有 `type` 字段**，`/create` 也不接受 `type`。因此：
> - 小程序里池类型恒为「手动维护」，「自动更新」统计恒为 0；
> - 创建股票池时选择的**行业与筛选条件不会随创建提交** —— 它们的作用只是把符合条件的股票算出来，最终入池的是股票代码。
> - 期望后端补充 `type` 字段（取值 `自动同步` / `条件筛选` / `系统自动` / `手动维护`）。小程序逻辑已按完整枚举写好，补字段后无需改代码。
>
> ⚠️ `/stocks` 不返回数量，股票池列表页必须逐池调一次取长度（N+1 请求）。若后端能在 `/list` 里带上 `stock_count` 会显著提速。

### 4.2 策略模板 `strategy`

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/api/strategy/list` | GET | 全部模板（公开接口，无需 token） |
| `/api/strategy/id/{id}` | GET | 按 ID 取详情，**含 `default_params`** |
| `/api/strategy/{name}` | GET | 按名称取详情 |

**模板字段**：`{ _id/id, name, strategy_type, description, default_params }`

> ⚠️ **`default_params` 是三层的**，与提交的 `strategy_params`（两层）结构不同：

```jsonc
// default_params —— 模板定义（含中文 desc 与默认值）
{
  "match": { "min_price": { "desc": "股价下限", "value": 3.0 }, "max_price": { "desc": "股价上限", "value": 100.0 } },
  "buy":   { "buy_ratio": { "desc": "买入仓位比例", "value": 0.25 } },
  "sell":  { "stop_loss": { "desc": "止损比例", "value": -0.08 } }
}

// strategy_params —— 用户保存值（提交时）
{
  "match": { "min_price": 5.0, "max_price": 80.0 },
  "buy":   { "buy_ratio": 0.3 },
  "sell":  { "stop_loss": -0.1 }
}
```

> ⚠️ `/api/strategy/list` **不返回 `default_params`**（列表接口精简）。因此创建/编辑策略页选中模板后必须**单独调一次 `/api/strategy/id/{id}`** 才能拿到参数定义。

### 4.3 用户策略 `user_strategy`

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/api/user_strategy/list` | GET | 我的策略列表 |
| `/api/user_strategy/create` | POST | 创建关联 |
| `/api/user_strategy/{id}` | PATCH | 局部更新 |
| `/api/user_strategy/{id}` | DELETE | 删除 |
| `/api/user_strategy/{id}/execution/latest` | GET | 最近一次执行结果（含 `positions`） |
| `/api/user_strategy/executions` | GET | 我的全部执行结果 |
| `/api/user_strategy/{id}/runlog` | GET | 运行日志（`skip` / `limit`） |

**`UserStrategyItem` 字段**：

```json
{
  "_id": "xxx", "id": "xxx",
  "name": "我的首板策略",
  "strategy_id": "模板ID",
  "user_id": "用户ID",
  "pool_id": "股票池ID",
  "status": "running",
  "initial_amount": 1000000.0,
  "total_profit": 23800.0,
  "max_stock_count": 4,
  "strategy_params": { },
  "create_time": "2026-09-01 10:00:00",
  "update_time": "..."
}
```

- `status` 枚举：`running` / `stopped` / `paused` / `error`；
- 展示名回退链（与 Web 一致）：`name` → 模板 `name` → `strategy_id` → 「未命名策略」；
- 主键兼容 `_id` 与 `id`，小程序统一 `String(us._id || us.id)`。

**`POST /create` Body**：

```json
{
  "strategy_id": "模板ID",
  "pool_id": "股票池ID",
  "status": "stopped",
  "initial_amount": 1000000.0,
  "max_stock_count": 4,
  "strategy_params": { },
  "name": "我的首板策略"
}
```

- `status` 小程序固定传 `"stopped"`（与 Web 一致：策略状态由服务端驱动，前端列表页不提供启停按钮）；
- **409 含义**：后端在 `error == "duplicate_name"` 时返回 409 —— 但对 create 路由，Web 侧把它解读为「该策略已关联，请在列表中编辑，请勿重复创建」。小程序按上下文分别提示。

**`PATCH /{id}` Body**（只传需要改的字段，后端 `None` 则跳过）：

```json
{
  "name": "...",
  "pool_id": "...",
  "initial_amount": 1000000.0,
  "max_stock_count": 4,
  "strategy_params": { }
}
```

> ⚠️ 可更新字段：`name` / `status` / `pool_id` / `initial_amount` / `total_profit` / `max_stock_count` / `strategy_params`。**策略模板本身（`strategy_id`）不可修改**。
> ⚠️ 全部字段为 `None` 时后端返回 **400「没有需要更新的字段」**。

### 4.5 交易信号 `trade_signal`

`GET /api/trade_signal/list`

| Query | 说明 |
| --- | --- |
| `stock_codes` | 逗号分隔，可选 |
| `strategy_id` | 可选 |
| `action` | `买入` / `卖出`，可选 |
| `start_time` / `end_time` | `YYYY-MM-DD HH:MM:SS` |
| `skip` / `limit` | 分页；⚠️ 默认 100，需显式传大值 |

**信号字段**：

```json
{
  "id": "xxx",
  "strategy_id": "用户策略ID",
  "user_strategy_id": "用户策略ID",
  "stock_code": "600519",
  "action": "买入",
  "trade_price": 1682.5,
  "profit_rate": 12.34,
  "profit_amount": 2380.0,
  "reason": "突破20日均线",
  "create_time": "2026-09-16 10:23:45"
}
```

- `action` 只有 `买入` / `卖出` 两个中文值；
- `profit_rate` **已是百分数**，不再 ×100；
- 小程序保留窗口：最近 `SIGNAL_RETENTION_HOURS`（12 小时）、最多 200 条。

> ⚠️ **`strategy_id` 与 `user_strategy_id` 是两个不同的东西，混淆是静默显示错误**：
> - `strategy_id` = **策略模板 ID**（`StrategyDao` 的 ID），多个用户策略可共用同一模板；
> - `user_strategy_id` = **用户策略 ID**（`UserStrategy._id`），唯一。
>
> 要「把一条信号挂到某个用户策略上」（例如策略列表的「最近信号」列、监控页的「策略」列、去重键），
> **必须用 `user_strategy_id`**。用 `strategy_id` 会导致：
> 1. 同一模板下的多个用户策略，信号互相串位；
> 2. 信号去重时把不同策略的同名信号误判为重复而丢弃。
>
> 唯一该用 `strategy_id` 的场景是「查模板信息」（拿模板名称 / 类型 / 描述）。

### 4.6 策略选股 `strategy_select_stocks`

`GET /api/strategy_select_stocks/list`

| Query | 说明 |
| --- | --- |
| `user_strategy_id` | 用户策略 ID |
| `start_time` / `end_time` | ⚠️ **必须传 `YYYY-MM-DD`**，传带时分秒会查不到数据 |

**返回 `StrategySelectStockWithRtItem`（已含实时行情，无需再查 `/real_time`）**：

```json
{
  "code": "600519",
  "name": "贵州茅台",
  "score": 88.50,
  "price": 1682.50,
  "change_percent": 0.0077,
  "change_amount": 12.80,
  "turnover": 0.0031,
  "rt_update_time": "..."
}
```

- 后端**已按 `score` 正向排序并对同 code 去重**，前端不得重排（会导致价格在刷新间抖动）；
- 只有 `ttm_pe`（`/api/finance/valuation`）与 `net_profit_growth_rate`（`/api/finance/profit`）需要用财务接口补两次。

| --- | --- | --- | --- |
| `/api/system_message/user_messages` | GET | — | 当前用户可收的系统消息（广播 + 定向），每条带 `is_read` |
| `/api/system_message/read` | POST | `{ id: "..." }` | 标记单条消息为当前用户已读，幂等 |

**返回字段**：`id` / `title` / `message` / `create_id` / `user_ids` / `create_time` / `is_read` / `read_count`

- `is_read`：**当前用户**是否已读。已读即归入历史消息，前端据此把列表分成未读 / 历史两段；未读条数由客户端按 `is_read` 统计，服务端不单独提供未读数接口。
- `read_count`：该消息的已读用户数（与当前用户无关）。
- `user_ids` 为空数组 = 广播，所有用户可见；非空时仅列表内用户可见。`read` 接口只能标记自己可见的消息，不可见与不存在都返回 404。

## 5. 【后端待新增】接口需求

以下 4 项是小程序端已按契约写好、**后端尚未实现**的能力。小程序侧均有降级行为，**不阻塞上线**；实现后无需改前端代码。

### 5.1 微信一键登录 `POST /api/user/wx_login`

**用途**：微信小程序平台的标准登录方式（一键授权，免输入账号密码）。

**鉴权**：匿名。

**请求**：

```json
{ "code": "wx.login() 返回的临时凭证 code" }
```

**后端处理**：调用微信 `code2session` 换取 `openid` / `session_key` / `unionid`：

```
GET https://api.weixin.qq.com/sns/jscode2session
    ?appid=APPID&secret=SECRET&js_code=<code>&grant_type=authorization_code
```

**响应 A — 已绑定平台账号**（`data`）：

```json
{
  "token": "xxxxx",
  "user_id": "xxx",
  "account": "xxx",
  "role": 1
}
```

与 `/api/user/login` 的响应结构保持一致，小程序复用同一套 `persistLogin()`。

**响应 B — 未绑定平台账号**（`data`）：

```json
{
  "need_bind": true,
  "bind_ticket": "一次性绑定票据（建议 Redis 存 5 分钟）"
}
```

小程序收到 `need_bind` / `bind_ticket` 后切换到绑定表单，再调 5.2。

**需要后端落地的事**：
1. 用户表增加 `wx_openid` / `wx_unionid` 字段（唯一索引）；
2. 若一个 `openid` 只能绑一个平台账号 —— 明确策略并在文档里写清；
3. `code` 只能使用一次、5 分钟过期，失败时返回明确 `detail`。

### 5.2 微信与平台账号绑定 `POST /api/user/wx_bind`

**用途**：首次微信登录的用户用已有平台账号完成一次性绑定。

**鉴权**：匿名（靠 `bind_ticket` 鉴权）。

**请求**：

```json
{ "bind_ticket": "5.1 返回的票据", "account": "平台账号", "password": "密码" }
```

**响应**（`data`）：同 5.1 的响应 A。

**后端处理**：
1. 校验 `bind_ticket` 有效性并**立即消费**（防重放）；
2. 校验账号密码；
3. 把该 `openid` 写入账号记录；
4. 返回 token 与会话信息。

**错误**：票据失效 → 401/410 且 `detail` 明确；账号已绑其他微信 → 409。

### 5.3 交易信号 WebSocket 网关 `GET /ws/trade_signal`

**用途**：小程序无法直连 MQTT（`wx.connectSocket` 只支持 WS/WSS，且 MQTT broker 的鉴权方式与小程序域名白名单不匹配）。需要后端把已订阅的 MQTT 信号转发为 WS 推送。

**连接**：

```
ws://<host>/ws/trade_signal?token=<Bearer token>
```

> ⚠️ **小程序 WebSocket 不支持自定义请求头**，token 只能走 query 参数。请后端按 query 取 token 并校验。

**推送帧格式**（小程序 `utils/ws.js::normalizeFrame` 兼容三种）：

```jsonc
// ① 单条
{ "id": "...", "user_strategy_id": "...", "strategy_id": "...", "stock_code": "600519",
  "action": "买入", "trade_price": 1682.5, "profit_rate": 0, "profit_amount": 0,
  "reason": "...", "create_time": "2026-09-16 10:23:45" }

// ② 批量
[ { ... }, { ... } ]

// ③ 带包体（与 HTTP 的 ApiResponse 一致也可）
{ "code": 0, "message": "ok", "data": [ { ... } ] }
```

**必须做到的两件事**：
1. **只推给该 token 归属用户**的信号（按 `user_id` 过滤），不能全量广播；
2. **新连接建立时先补推最近 12 小时的历史信号**，否则小程序首屏会空白（当前降级方案是靠一次 HTTP 轮询兜底）。

**心跳**：小程序每 25s 发送 `{"type":"ping","ts":<毫秒>}`，请后端回 `pong` 或忽略，不要因此断连。

**降级行为**：WS 连不上且连续失败 2 次后，小程序自动切到 HTTP 轮询 `/api/trade_signal/list`（监控页 3s、仪表盘 10s），同时指数退避重连；WS 恢复后自动切回。**因此本接口未实现时，功能只是实时性下降，不会不可用。**

### 5.4 【建议】`PoolInfo` 补 `type` 字段与 `stock_count`

```json
{
  "id": "xxx",
  "name": "核心持仓池",
  "description": "...",
  "type": "手动维护",          // 新增：自动同步 | 条件筛选 | 系统自动 | 手动维护
  "stock_count": 32,          // 建议新增：省掉 N+1 次 /stocks 请求
  "create_time": "...",
  "add_time": "..."
}
```

- `type` 缺失导致池类型恒为「手动维护」、「自动更新」统计恒为 0；
- `stock_count` 缺失导致股票池列表页需要逐池调 `/stocks` 取长度（N+1 请求），池多时首屏明显偏慢。

前端逻辑已按完整枚举写好，后端补字段后**无需改前端代码**。
